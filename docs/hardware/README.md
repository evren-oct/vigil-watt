# 硬件协议文档

> 按**文档职责**分三层，不按品牌数量分。新增设备文档时先看下面的「放哪」判据，别凭手感。
> 所有结论都是真机验证或官方软件抓包所得；零写入原则见 [safety.md](safety.md)。

## 放哪

| 你写的是 | 放这 | 判据 |
|---|---|---|
| 某个品牌下的设备怎么读电量（可含多个型号） | `brands/` | **文件名 = 品牌名**。品牌出第二个型号时只加章节，不搬家 |
| 单个型号的深挖（耳机、适配器、单型号鼠标） | `devices/` | **文件名 = 型号名**，或跨品牌的复合名 |
| 厂商软件里逆出来的型号表 / 命令表 / 档位表 | `reference/` | 静态资料，不描述实时协议 |
| 跨品牌规则（红线、来源、抓包手法、索引） | 本层根目录 | 不属于任何品牌 |

品牌名与型号名的边界只有一个例外：**跨品牌合写的文档用复合名进 `devices/`**（现例：`ak870-ml903.md` 同时讲黑爵与雷神）。这类文档是拆分候选，不是命名范本。

## 本层文件

| 文件 | 用途 |
|---|---|
| [protocols.md](protocols.md) | **索引**：品牌 / 型号 / VID:PID 对照表、共用号段陷阱、官方资料地图 |
| [safety.md](safety.md) | 硬件写入红线与事故复盘；任何写入改动前必读 |
| [sources.md](sources.md) | 协议依据、外部参考与许可边界；追溯来源先看这里 |
| [debugging.md](debugging.md) | 官方软件抓包、HID 观测与单帧验证步骤 |

## 三个子目录

- **`brands/`**（23 份）：一品牌一份。品牌内多套协议写在同份里，按 `## n.` 分节；跨品牌共用号段的分流判据在各文档里交叉引用。
- **`devices/`**（13 份）：单型号专题。耳机、适配器、只有一台设备的鼠标都在这；写的是这一型号的接口地图、帧格式与验证边界。
- **`reference/`**（3 份）：厂商软件逆向出的静态资料。查「这个品牌有哪些型号」「DPI 有哪些档」看这里，查「帧怎么发」看 `brands/`。

## 改协议代码前

1. 先在 [protocols.md](protocols.md) 的对照表里按 VID:PID 找到品牌文档；
2. 读该品牌文档对应小节，不要重新猜协议；
3. 涉及写入的，先读 [safety.md](safety.md)；
4. 新增型号先改 `specs/*.protocols.json`，写法见 [../dev/protocol-json.md](../dev/protocol-json.md)。
