# AKG N9 Hybrid 接收器电量

## 1. 协议依据与真机样本

接收器 `0ECB:20D9`，仅处理 MI03 Col02 的 `FF13/0001` 厂商集合：输入、输出均 62 字节，输出报告 ID `06`，无 feature 报告。其它消费控制、电话控制和 Col04 集合均不访问。认领规则在 `AkgN9Codec.IsSupportedInterface`，不按品牌号段扩大范围。

[HeadsetControl 的 Airoha 协议实现](https://github.com/Sapd/HeadsetControl/blob/master/lib/devices/audeze_maxwell_device.hpp) 提供了 RACE 封装与 `0CD6` 电量查询依据。本项目按协议与 N9 实测帧独立实现，没有复制该项目源码。

普通中断输入被动监听 65 秒没有数据；本机 N9 的 `GET_INPUT_REPORT(07)` 曾读到消息片段。这是设备特定的控制读取行为，不能推广成 Windows API 的队列语义：[微软文档](https://learn.microsoft.com/en-us/windows-hardware/drivers/hid/obtaining-hid-reports)将它用于当前状态读取，并指出连续获取可能丢报告。报告布局：`07 <有效长度> 80 <片段> <旧缓存>`，有效长度 0–59，长度之外的字节必须忽略。一个片段可能包含多条消息，也可能只含一条消息的一部分。

消息布局：`05 <类型> <消息体长度 LE16> <命令 LE16> <参数>`。支持读取 `5B` 响应、`5C` 通知和 `5D` 异步结果。消息总长限定 6–1024 字节，出现格式错误即结束本轮，不扫描命令或猜测偏移。

固定查询（62 字节）：`06 07 80 05 5A 03 00 D6 0C 00`，余下 52 字节为零。

2026-10-23，经用户明确允许发送一次查询，收到输入有效片段：

```text
07 10 80 05 5B 03 00 D6 0C 00 05 5D 05 00 D6 0C 00 00 32
```

其中 `10` 表示 16 字节有效片段，包含成功 ACK `05 5B 03 00 D6 0C 00` 和结果 `05 5D 05 00 D6 0C 00 00 32`。结果的状态与目标角色均为 `00`，末字节 `32` 为十进制 **50%**。ACK 本身不是电量；错误状态、非目标角色和超出 0–100 的数值均拒收。实际报告的剩余字节仍有旧消息，单测保留完整 62 字节样本防止误读。

## 2. 插件行为与验证边界

- 设置页只列“爱科技 / AKG”品牌开关，`PluginEnabled["Akg"]` 默认关闭。关闭时基类跳过探测，固定查询的写点也检查同一开关和完整接口身份。
- 每轮先在约一秒窗口内最多读取 20 次，确认有效长度为 0 的空闲态后才发送一条查询；空读或其它 report ID 在窗口内重试读取，持续非空、持续失败或格式错误则不写入。结果阶段最多读取 60 次，间隔 50ms，窗口约三秒，空读或其它 report ID 同样等待至窗口结束；单次原生调用仍受 Windows HID 超时影响。不重发查询，不发送配置或会话命令。
- 仅在本轮响应阶段比较相邻非空报告的有效区域，忽略尾部旧缓存变化，重复快照不再追加到拼接器；长度 0 或新一轮查询会重置比较状态。不会要求本轮 ACK / 电量不同于上轮；稳态两轮完全相同仍可采纳。无序号时无法完全区分重复状态与字节恰好相同的连续片段，不能据此保证任意长通知流完整交付。
- 每次查询独立等待成功 `5B` ACK，忽略它之前的 `5D` 结果，包括同一报告中先于 ACK 的旧消息；未收到 ACK 则不采纳电量，上一轮的 ACK 不延续到下一轮。
- 成功 Info 日志按电量变化记录，包含 `原始=<HEX>`，内容仅为命中的电量结果消息，不包含报告尾部的旧缓存。Debug 另逐轮记录排空尝试序号、有效长度、报告前四字节及最终采纳的结果，供复核空闲态；不开 Debug 时不生成这些逐次日志。
- 不启动中断输入监听，不参加 15 秒快速发现；探测采用基类线程池路径，正常轮询使用基类 I/O 锁、连续失败熔断与递增退避。
- 只报告电量，充电状态固定为 `Unknown`。此前 Python 脚本与编译出的 C# 插件均读到 50%，C# 还验证了关闭开关不认领、初次认领后不立即重复查询、关闭后不轮询，最后释放句柄。2026-10-24 用户观察到耳机无法在充电状态下工作，并明确取消充电测试；这是用户反馈的使用限制，本次未做插拔充电对照，不推断充电标志。官方 App 对照、电量变化和关机行为仍待验证；USB 有线和电脑蓝牙连接不在本次适配范围内，见 CR-84。
- 新增 `HidDeviceHandle.GetInputReport`，只调用 `HidD_GetInputReport`，已有中断输入与 feature 路径不变。验证时避免其它程序同时查询接收器，以免影响设备状态与观测结果。

纯逻辑测试直接链接 codec、分片拼接器与传输循环，覆盖真实帧、旧缓存、分片/合并、边界长度、错误响应、开关关闭、空闲态确认、重复快照、ACK 时序和无重试。固定协议未携带逐轮事务号，等待 ACK 能排除它之前的迟到结果，仍不能保证区分新 ACK 之后到达的旧结果。有限真机样本不能替代异常路径验证，也不能证明充电状态可读取。
