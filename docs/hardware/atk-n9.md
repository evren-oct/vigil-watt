# ATK N9 系列耳机（dongle `373B:1204`）—— 协议已记录，**代码未实现**

> 协议与样本来自贡献者 2026-10-19 的采集包（真机 21:00~22:25，含 432 条 2.4G 采样与 121 条蓝牙采样）。
> **本仓库没有这台设备，未复测**；也**没有实现插件**，原因见 §5。索引见 [protocols.md](protocols.md)。

## 1. 关键事实：电量不走 HID

`373B:1204`（`ATK N9 Ultra dongle`）是复合设备，5 个接口：

| interface | 类型 | 说明 |
|---|---|---|
| MI_00 | USB Audio | 音频端点 |
| MI_03 | HID `0xFF02/0x0002` | 厂商口，Input/Output 64B |
| MI_04 | HID `0x000C/0x0001` | Consumer Control |
| **MI_05** | **CDC-ACM** | **Class 02/02/01、`Service=usbser`、`PortName=COM4` ← 电量在这** |

MI_03/MI_04 两个 HID 口被动监听 4 轮共 145 秒（含耳机开机、正在播放音频、官方 ATK HUB 运行中）**全部 0 帧**。按 HID 找永远找不到，这是适配这台设备最容易踩的坑。

## 2. 串口参数与定位

- 串口名从设备树取，不要硬编码 COM 号：
  `HKLM\SYSTEM\CurrentControlSet\Enum\USB\VID_373B&PID_1204&MI_05\<inst>\Device Parameters\PortName`
- 9600 / 8 / None / 1，无流控（抄自 ATK HUB 的 `app.asar`）。

## 3. 帧（64 字节定长，无帧头、无校验、无转义）

```
发（GetBattery）：02 00 03 00 00 … 全 0
                  │  │  └ subCmd = 3
                  │  └─── cmd = 0 (AUTH)
                  └────── len = payload + 2

收：04 00 03 00 3C 00 … 全 0
                ↑ rx[4]
```

- 电量 = `rx[4] & 0x7F`
- 充电 = `(rx[4] >> 7) & 1`

## 4. 充电位是有的，但充电时百分比是占位

实测 `0x3C`(60%) → 插线 `0xE4`（bit7=1，低 7 位=100）→ 拔线 `0x46`(70) → 约 40 秒后回落 `0x3C`(60%)。

耳机电池不可能 2 分钟从 60% 充到 100%，所以**充电态的低 7 位不能用**：bit7=1 时只报「充电中」，百分比沿用上次放电态的值。

## 5. 为什么还没实现

1. **通道不是 HID**：基类 `BatteryPluginBase` 持有的句柄类型是 `HidDeviceHandle`，`AttachAsync` 拿到的也是 HID 接口列表。串口设备既不会被 HID 扫描发现，也没法复用基类的探测/轮询骨架。
2. **R2 没有例外**：项目硬规矩是插件必须继承 `BatteryPluginBase`（历史事故的唯一成因），全仓只有罗技一处豁免。要接串口，得先给基类加一层「传输」抽象，或者明确豁免——两者都是设计决定，不是移植代码。
3. **品牌只能一行**：ATK 是 `0x373B` 品牌，按 `AGENTS.md` §9 设置页只留一行开关。鼠标那套（HID，`Plugins/Atk`）已经在做，耳机要落地必须并进同一个 ATK 插件，否则会出现两个 `AtkPlugin`、两个 `Atk` 开关。

所以本文件只记录协议，代码等上面三条有结论再动。

## 6. 已知未解

- **读数在两个值之间来回跳**：`rx[4]` 会在 `0x3C`(60) 与 `0x32`(50) 之间跳，两帧除该字节外完全相同，间隔不规则（9.3s / 12.3s / 18.5s / 21.6s / 49.4s / 120.4s 都出现过），**原因不明**。贡献者的兜底是「连续 2 次一致才发布」，落地时照做。
- **串口是独占的**：ATK HUB 运行期间 `open()` 一直 `PermissionError(13)`（300 秒内每次都失败），完全退出后立刻成功。也就是说本应用与 ATK HUB 不能同时读这台耳机，界面上应该提示二选一——这条还没做。

## 7. 未验证项

1. **休眠 / 关机**两态都没测（只测到串口被占用）。
2. **拔线后先报 70% 约 40 秒再回落 60%**：状态切换后短时间内读数不稳，落地时需要去抖窗口。
3. 蓝牙模式下是否也能读到电量，未确认。
