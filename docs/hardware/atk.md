# ATK 2.4G 鼠标与键盘电量

> 接收器 `VID_373B`（ATK / 艾泰克，深圳意义之塔科技）。**鼠标走 16 字节 op 帧，键盘走 VIA**——同一个 VID 下按 usage page 分流。
> 协议由贡献者 Gpan666 在本机 Python 探针与 VigilWatt 1.2.1 本地构建上验证；本仓库代码由 AI 辅助编写，只做到编译 + 单测通过，维护者未复测。
> 索引与其它设备见 [protocols.md](protocols.md) §13。

## 1. 实测身份

同一个接收器会枚举出多个厂商集合。认领必须同时满足下表全部条件：

| 链路 | VID / PID | usage page | 输入 / 输出长度 | report ID |
|---|---|---|---|---|
| 鼠标 | `0x373B` / `0x11D9`、`0x11E4` | `0xFF02` | 17 / 17（**已含 report ID**） | `0x08` |
| 键盘 | `0x373B` / `0x1152` | `0xFF60` | 33 / 33（含前导 `0x00`） | `0x00` |

- 鼠标判据见 `AtkCodec.IsSupportedInterface`，键盘判据见 `AtkViaCodec.IsSupportedInterface`。
- 键盘判据只看 `usagePage == 0xFF60` + 进出等长 + `≥5` 字节 + report ID 为 `0x00` 或未知；**不按长度死锁 33**——VIA 通道的 report 长度随厂商实现浮动（GANSS 也是 33，但不是同一套命令）。
- **产品串不能当判据**：`11E4` 的产品串是 `ATK F1 ULTIMATE 2.0`（不含 "mouse"），而 `11D9` 是 `Wireless mouse 8k dongle-L`。型号名只按 PID 查表（`AtkPlugin.KnownModelByPid`），认不出的 PID 按鼠标图标显示。
- 键盘链路必须排在鼠标前面：两者 VID 相同，只靠 usage page 分流；反过来会把 VIA 查询帧发给鼠标。

## 2. 鼠标：16 字节 op 帧（report `0x08`）

帧结构（`AtkCodec`）：

```
[0] op  [1] ctx  [2] addrH  [3] addrL  [4] len  [5..14] data×10  [15] chk
chk = (0x4D - sum([0..14])) & 0xFF
```

查询帧是 `op = 0x04`（电量），其余补零：

```
08 04 00 00 00 00 00 00 00 00 00 00 00 00 00 00 49
^report ID                                      ^chk
```

响应里 `data[0]`（即帧内偏移 `[5]`）就是电量百分比。实测 `08 04 00 00 00 00 55 … F4` = 85%。

- **必须校验和通过**：键盘通道会把 op 帧原样回显、且 `data[0]` 是与电量无关的常量（实测恒 `0x29` = 41），回显帧的校验和还是主机发出去的旧值——校验和是唯一能挡住它的判据（`AtkCodec.TryParse`）。
- `0` 与 `>100` 在协议层判无效：设备休眠时接收器会回 0，与"真的 0%"无法区分。
- report ID 在不在缓冲里都可能，解析时两种偏移都试。

## 3. 键盘：VIA 读键盘值（page `0xFF60`）

ATK 键盘的厂商方案（HFD / BYKB）在标准 VIA 之上加了一层 `customId` 扩展：

```
[0] 0x00（前导）  [1] 0x02（id_get_keyboard_value）  [2] 0x96（customId）  [3] 0x24（battery）
```

响应实测 `00 02 96 24 64 01 …`：

| 偏移 | 含义 |
|---|---|
| `[0]` | 前导 `0x00`（不是 report ID，解析时跳过） |
| `[1]` | `0x02` 命令回显 |
| `[2]` | `0x96` customId |
| `[3]` | `0x24` 电量键 |
| `[4]` | **电量百分比**（样本 `0x64` = 100） |
| `[5]` | 充电标志：非 0 = 充电中 |

- 解析要求 `[1..3]` 三个命令字节全部对上（`AtkViaCodec.TryParse`），两种偏移都试（带/不带前导 `0x00`）。
- 官方客户端在充电时不显示百分比（`power = 0 === batteryCharge ? batteryLevel : undefined`）；本插件照读数显示并标"充电中"。
- **不要用 op 帧读键盘**：`0xFF60` 接口对 op 帧只回显请求，`data[0]` 恒为 `0x29`，校验和不重算，读出来必然是 41%——这是本项目踩过的坑。

## 4. 安全边界

- **会写帧**：鼠标发 op 帧、键盘发 VIA 查询帧，故走 `AppSettings.PluginEnabled["Atk"]`，默认 `false`。**没有按型号分开关**：设置页是品牌级开关（`AGENTS.md` §9），开「艾泰克」即授权向鼠标、键盘发送各自工作所需的帧。
- 实现位置：帧结构在 `AtkCodec` / `AtkViaCodec`（纯函数，有单测），I/O 在 `AtkPlugin`（`QueryMouse` / `QueryVia`），协议名 `atk-mouse-op04` / `atk-keyboard-via`，图标由 `ResolveKind` 按协议给 `Mouse` / `Keyboard`。
- 参与 15 秒发现节拍（`SupportsDiscoveryProbe`），`ProbeCooldown` 10 秒；未认领时每拍最多 1 条查询帧，认领成功后零写入。
- 熔断与退避沿用基类：连续 3 次无应答 → 停写 + 标离线，退避 30 秒起、封顶 5 分钟。`Offline.CountPollFailures = false`，由 `PollDevice` 在确实发过帧的分支自己报账。
- **鼠标失败不报账**（键盘报账）：2.4G 鼠标空闲即睡，查询无应答是常态；一报账就触发退避，读数会被冻住最长 5 分钟，表现为"刷新了也不更新"。代价是鼠标关机时不会立刻标离线（接收器还在，设备列表保留上次读数）。
- 无应答只在状态变化时记一条 Debug（`Log.Once` + 成功即复位），不逐次记 WARN。
- **读数过滤器**：`AnomalyPersistWindow` 覆写为 1 分钟。ATK 帧自带校验和 / VIA 响应自带命令回显，不会有"读成随机字节"的伪信号；基类默认 5 分钟对"鼠标充到 100%"这类真实跳变太慢。

## 5. 未验证项

- **鼠标只在 85% / 100% 两个点验证过**：低电量段是否线性、休眠时会不会报 0，样本不足。
- **鼠标型号表只覆盖三只设备**：`11D9` / `11E4` = ATK F1 Ultimate 2.0，`1152` = ATK A98 Pro。其余 ATK PID 默认按鼠标算，但型号名会退回产品串。
- **键盘充电标志只验证过 0 和 1**：其他取值一律按"非 0 = 充电中"处理。
- **VIA 通道长度不固定**：本机 33 字节，其它 ATK 键盘是否同长度未验证；判据已放宽到 `≥5`。
