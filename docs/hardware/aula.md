# AULA 键盘电量协议

> 从 [protocols.md](protocols.md) 拆出（2026-10-21）。结论均来自真机验证或官方软件抓包；改协议代码前先读本文。

## 1. AULA F99 Pro（接收器 VID_3554&PID_FA09）—— 贡献者真机声明，本机未复测

厂商集合 `0xFF02/0x0002`，report `0x13`，进出各 20 字节，和迈从 G87 的接口指纹一致，因此复用 `MchoseV1Codec`。只发送贡献者在本机见到的开会话帧 `13 05 01`，不发送无应答的 `13 4A`。推送 `13 0A` 的 `[6]` 是电量，`[7]` 的 `0x10` 位表示充电。

插件默认关闭。不参加 15 秒发现节拍，避免未认领时把会话帧抬到大约每 15 秒一次；打开后只跟 60 秒主轮询。迈从插件不再整段排除 `0x3554`，改为按会话 ACK 型号分流（§1.1）。

### 1.1 与迈从 G75、凌豹 K98 的认领冲突（2026-10-24/25）

`3554:FA09` 被三家共用，接口指纹（`0xFF02/0x0002`、20/20）与帧格式完全一致，HID 层分不出品牌。只能按**会话 ACK 的型号码**分流：

| 型号码 | 归属 |
|---|---|
| `0x0158` | AULA F99 Pro（本插件） |
| `0x00A4` | AULA F99（非 Pro，本插件，见 §1.2） |
| `0x0212` | 凌豹 K98（`LingbaoPlugin`，见 [lingbao.md](lingbao.md) §2） |
| 命中迈从型号密码表 | 迈从 G75（`MchosePlugin`，见 [mchose.md](mchose.md) §5） |

- 迈从插件不再整段排除 `3554`，只放行这条精确指纹，并在探测阶段要求 ACK 密码命中迈从型号表；
- 本插件在 `TryRead` 里看到型号不是 `0x0158` / `0x00A4` 就返回 null，把接口留给另外两家——**与对方开关是否打开无关**，因为设备本身不是狼蛛的；
- 凌豹插件排在 AULA 之后，共用路径上会等 AULA 先探完再认领（`LingbaoPlugin.AttachAsync` 里的 2 秒等待）。

AULA 自己的真机 ACK 密码是 `03 00 00 00 01 58`（型号码 `0x0158`），不会被误判（`AulaProtocolTests` 有回归）。

### 1.2 F99（非 Pro，型号码 `0x00A4`）—— 贡献者采集包，本机未复测

接口（`0xFF02/0x0002`、进出 20 字节、report `0x13`）与帧格式和 F99 Pro **完全相同**，因此共用同一条解析路径，只多认一个型号码。

来源：2026-10-29 采集包（v1.3.1，零写入，105 秒 / 30 帧 / 0 错误）。会话 ACK 与推送成对自发，ACK 每次相同：

```text
ACK     13 05 01 00 0A 03 00 00 00 00 A4 01 … CB     # 型号码 0x00A4
73% 放电 13 0A 01 00 04 05 49 01 … 71
80% 充电 13 0A 01 00 04 05 50 10 … 87
```

- 30/30 帧校验和通过（Σ`[0..18]` & 0xFF）；`[6]` 电量 73~81，`[7]` 的 `0x10` 只在插电区间置位、拔掉后归 `0x00`，与 §1 一致。
- ACK 与推送的间隔是 15.0 / 4.3 / 10.6 秒三拍循环（采样期内重复两遍），像是固件自己的节奏。**不能据此改成纯被动**：无法排除采集时官方驱动在跑，需一次关掉官方软件的对照采集才能定。
- 显示名仍沿用「AULA F99 Pro」：`BuildDisplayName` 只拿得到接口信息，要按型号码区分得改基类签名，2026-11-01 决定不动基类。型号只在日志里区分。

## 2. HERO 68 Air（8K 接收器 372E:106C）

2026-10-23 贡献者真机验证：2.4G 电量 **10%**，未接线状态 `0x00`（放电），接充电线并保持 2.4G 后状态 `0x10`（充电）。实际 `AulaPlugin` 完成认领和后续轮询；关闭 `Aula` 开关不再查询。满电、中间电量、拔插恢复尚未真机验证，不据此宣称支持其他 HERO 型号或 USB / 蓝牙模式。

### 2.1 官方来源与接口

依据 [A HUB 官方在线驱动](https://hub.aulacn.com/checkDevice) 的公开前端协议行为独立实现，没有复制厂商源码或资源：

- [index-GW9ckk1o.js](https://hub.aulacn.com/assets/index-GW9ckk1o.js)：`er()` 用 UUID `0x12000000000A` 识别 HERO 68 Air；`372E:106C` 也用于 HERO 68 XS、HERO 75 HE、HERO68 MINI Air，不能仅凭 VID/PID 认领。
- [vendor-DTzSSMIf.js](https://hub.aulacn.com/assets/vendor-DTzSSMIf.js)：`gFe.loadUuid/getBatteryStatus`、`rFe`、`GFe`、`UFe` 定义固定查询、业务帧、8K 分片及 ACK；`S2e` 定义充电/充满标志。

本机 HID 描述符为 `FF60/0061`、report ID `09`、输入/输出各 **20 字节**。同一接收器的 `FF02/0002` 是另一套 17 字节通道，不得向它写入此协议。接口判定同时核对 VID、PID、usage、长度和 report ID，取得正确 UUID 后才发电量查询。

### 2.2 业务帧与读数

主机业务包共 64 字节，含首字节 report ID `09`；接收包为 63 字节，不含 ID。下表偏移以**接收包**为准：

| 位置 | 含义 |
|---|---|
| `[0]` / `[1]` | 命令 / 参数：UUID `82 01`，电量 `87 00` |
| `[2..4]` | 保留位、业务包总数、当前业务包：`00 01 00` |
| `[5]` | 数据长度：UUID `06`，电量 `02` |
| `[6..]` | UUID 六字节大端；或电量百分比、状态字节 |
| `[62]` | 所有业务字节加上 report ID `09` 的和取低八位必须为 `FF` |

UUID 查询前七字节为 `09 82 01 00 01 00 06`，其余补零，末字节 `6C`；电量查询为 `09 87 00 00 01 00 00`，末字节 `6E`。只使用这两条官方命令。接收侧校验完整长度、命令、参数、包序号、数据长度和校验和；百分比超过 100 拒绝。

真机响应（`…` 均为补零，完整长度 63）：

```text
UUID       82 01 00 01 00 06 12 00 00 00 00 0A … 50
10% 放电   87 00 00 01 00 02 0A 00 … 62
10% 充电   87 00 00 01 00 02 0A 10 … 52
异步推送   FE 05 0A 00 … E9
```

状态字节高四位非零表示充电，低四位非零表示已满；充电优先。未置位时按放电处理，不用百分比猜充电标志。查询期间收到完整 `FE 05` 异步推送时，完成 ACK 并忽略它，继续等待 `87` 响应；当前仅支持完整包之间的穿插。若通知插入尚未收齐的响应分片之间，重组器会重置并使本轮失败，不误报电量；传输层离线回归与进一步支持见 CR-97。

### 2.3 无线分片和安全边界

64 字节查询拆成五片（14/14/14/14/8 字节）；63 字节响应同样五片，末片 7 字节。每个 HID 报告含 `09` 加 19 字节正文，正文结构如下：

```text
66  total|sync.bit2  current|sync.bit1  length|sync.bit0  payload  sum  padding
```

总片数、当前片号、长度各占低七位，高位承载三位循环序号；每片序号递增并对 8 取模。校验和为正文从 `66` 到 payload 的低八位加和，不含 `09`。ACK 保留 `66`、总片数、片号及 sync 位，将长度低七位清零并重算和。每发一片先等匹配 ACK，再发下一片；每收一片先回 ACK，再按顺序重组。

`AulaHero68PacketAssembler` 有界重组 63 字节，拒绝乱序、序号跳变、超长或校验不符的报告，忽略已收分片的重传。完整包再经过业务校验，避免异步通知污染查询结果。

与 F99 Pro 共用 `PluginEnabled["Aula"]`，默认关闭，不进入 15 秒发现。UUID 是每句柄的身份握手，后续每轮只发一次电量逻辑查询；分片与必要 ACK 属于这次查询。每片及 ACK 都重新检查品牌开关和接口。单片 ACK 最多等 500ms，每个逻辑查询接收窗口 3 秒，最多回复 15 条 ACK，超时不重发、不换命令。实际失败交由基类三次熔断及递增退避处理。

### 2.4 验证范围与复测

- 已验证：官方 UUID、10% 放电及接线充电、实际插件认领和重复轮询、品牌开关关闭、句柄释放；单测覆盖真实响应、共享接收器的其他 UUID、查询字节、ACK 及分片边界。
- 真机曾在闲置后对固定查询无回应；用户按键唤醒后同样的查询恢复。沿用现有查询型插件的失败/退避策略，休眠与断连的跨插件问题见 `../reviews/BACKLOG.md` CR-81。
- 待复测：满电和中间电量、实际休眠/唤醒恢复时长、接收器拔插、不同固件。USB 与蓝牙暂不接入。
- 验证前退出其他持有设备会话的软件；保持 2.4G 并唤醒键盘。只启用「狼蛛 / AULA」，核对列表名称、原始帧和电量；接充电线时保持 2.4G，确认状态切换。不做命令枚举或报告 ID 扫描。

## 3. G9 耳机（接收器 `38A6:0030`）—— 贡献者声明，本机未复测

**纯被动、零写入**，可换电池机型。厂商集合 `0xFFAB`（64 字节双向），耳机每秒推一条状态帧：

```
AB 47 4D 86 …  [6]=电量%  [7]=充电标志（0x02 = 充电中）
```

- 固件 V0.0.4 的签名：电量 `0` + 标志 `0` = **没在报数**，不是真空电，此时只报"在线无读数"。
- 换电池会跳几十个点，所以本插件把单步变化上限放到 100（不拦跳变）。
- 状态帧每秒一条，10 秒静音判离线；没有查询命令，轮询返回 null 不算失联。
- 参与 15 秒发现节拍（零写入），`ProbeCooldown = 5 秒`。

**为什么它是独立插件类**：`SupportsPassiveListen` / `SupportsFastDiscovery` / `Offline.Silence` / `MaxPlausibleStepPercent`
都是**插件级**配置，而 AULA 的会话型协议（F99 Pro / HERO 68）恰恰需要相反取值（不被动听、不进 15 秒档、沉默不判离线、单步 20）。
硬折进 `AulaPlugin` 会把两边都改坏。所以 G9 保留自己的类，但 `Name` 同为 `Aula`、共用同一个品牌开关，
设置页按 `Name` 去重后**只出一行**（`AGENTS.md` §9）。插件级策略按型号分化见 `reviews/BACKLOG.md` CR-102。

## 4. L9 Ultra 鼠标（接收器 `38A6:28FD`）—— 贡献者声明，本机未复测

接收器枚举 4 个厂商接口，**只有 `0xFFA8` 应答**（`OutputReportLength ≥ 3`、`InputReportLength ≥ 11`），其余不认领。

查询：发 `0B 81 00…`（report ID `0x0B` + 状态命令 `0x81`）；回包 report ID `0x0A`：

```
0A 81 …  [17]=充电标志（0/1）  [18]=电量%
```

电量在 `0x81` 回包而非 `0x85`（官方 JS 的命令表与实际协议不一致，见 `protocols.md` 的教训）。
会写帧，故与 F99 Pro 共用 `PluginEnabled["Aula"]`、默认关；只在 60 秒主轮询里查，不进 15 秒发现。
