# 阿斯盾 AUSDOM G04 接收器电量

> 从 [protocols.md](protocols.md) 拆出（2026-10-31）。结论均来自真机采集；改协议代码前先读本文。

## 1. AUSDOM G04 Ultra 8K 接收器（VID_363C&PID_FF9D）—— ✅ 被动电量帧已确认

采集来源：`vigilwatt-capture.zip`（方法 usb-hid 只读采集，未向设备写任何字节）。设备名 `G04 Ultra 8K Dongle`，厂商 `AUSDOM`，固件版本 `0x0220`（544）。接口 `VID_363C&PID_FF9D&MI_01&Col05`，usage page `0xFFA0`、usage `2`，输入报告长度 **64** 字节、输出 256 字节、无 feature 报告；输入 report ID 集合为 `[10, 161]`，输出为 `[11, 162]`。

### 1.1 帧布局（report ID 0x0A，64 字节，仅前几字节有意义）

```
B0 = 0x0A           报告 ID
B1 = 0x12           状态子类型（电量由此类帧读出）
B2 = 0x05           正常态（携带电量）；0x02 为关机/子帧，不报电量
B3 = 状态/计数器    C4 / C7 = 短帧；C6 = 长帧；其它值待观察
B4.. = 负载
```

- **短帧（B3 = C4 / C7）**：`B4` 即电量百分比。真机 `0A 12 05 C4 5E` → 94%，`0A 12 05 C4 5F` / `C7 5F` → 95%。
- **长帧（B3 = C6）**：`B4 == 0` 且 `B5 == 0x02` 时，电量在 **B6**。真机 `0A 12 05 C6 00 02 5E` → 94%，`…5F` → 95%。
- 非电池子消息：`B4 ∈ {0x00, 0x01}`（如 `0A 12 05 C6 01`、`0A 12 05 C7 00`）。这些帧在充电中、断开后都出现过，**不是充电标志**，解析时直接忽略；其 `B4=0x01` 若误当电量会被基类异常过滤器（MaxPlausibleStepPercent=20）在 94→1 跳变处拦下，但 codec 层面已先剔除。
- 其它 report ID 0x0A 子类型：`0x13` 为信息帧（含 MAC `FE F1 E5 1C 0C B0`，电量在 B18=`0x5E`=94），是**空闲周期心拍**——采集里每隔 ~3-4 秒发一次、内容稳定，是设备睡着时唯一稳定的信号源，插件同样读它（见 §1.2）；`0x14` 为空帧。

### 1.2 插件行为

- 新建 `Plugins/Ausdom/AusdomPlugin.cs`（继承 `BatteryPluginBase`，遵循 R2）与 `AusdomCodec.cs`（纯帧解析，便于单测）。设置页只需 `PluginEnabled["Ausdom"]`，**默认关闭**（新品牌默认关）。
- 纯被动零写入：`WritesEnabled=false`、`ProbeWrites=false`、`SupportsPassiveListen=true`、`SupportsFastDiscovery=true`，探测只被动听 5 秒 `0x0A` 帧，不发任何字节；`ProbeCooldown=5s`。
- 探测同时接受两类 `0x0A` 帧：`0x12` 状态帧（短帧 B4 / 长帧 B6 载电量，仅在交互/状态变化时出现）与 `0x13` 信息帧（B18 载电量，空闲时 ~3-4 秒一发的周期心拍）。后者是解决「设备插着但鼠标静置时认领不到」的关键——纯 `0x12` 探测会在静置时 5 秒听不到任何帧而静默失败。
- `IsCandidate`：VID 363C && PID FF9D && usagePage 0xFFA0 && usage 0x0002 && InputReportLength == 64（严格多滤，只收 64 字节电量通道，避开 0x0001/0x0002、0x0001/0x0006、0x000C、0xFFB1 等其它集合）。
- 离线策略 `Confirm=6s / Silence=90s / CountPollFailures=false`（与雷柏、英菲克同款被动策略一致）：收到任何报文即存活，长时间静默兜底离线；零写入故 `PollDevice` 恒返回 null 属协议形态而非失联。
- `BuildDisplayName`：优先用产品串（如 `G04 Ultra 8K Dongle`），空则退回「阿斯盾 (VID_363C&PID_FF9D)」。

### 1.3 充电状态（✅ 已实测确认，B6 为低有效充电位，0x01=充电）

三次采集（vigilwatt-capture.zip、20261101-135550、20261101-140047）都做了「连接充电器」「断开充电器」人工标记。唯一随插拔变化的字节是短帧（`B3=C4`）的 **B6**（byte6，即 `C4 XX YY ZZ` 里的 `ZZ`，仅观察到 `0x00`/`0x01` 两个值）。

**真机实测修正（2026-11-01）**：初始按第三次采集（140047）的观察上线了 `01=放电 / 00=充电`，用户实测反馈**充电状态相反**。核对第二次采集（135550）与实测日志（`14:45:24` 电量 90% `C4 5A 00 00`→充电中、`14:45:35` 91% `C4 5B 00 01`→放电中）后确认正确方向为：

| 阶段 | 帧 | 电量 | B6 |
|------|----|------|----|
| 充电 | `C4 5C 00 01` | 92% | **01** |
| 放电 | `C4 5C 00 00` | 92% | **00** |

结论（已固化）：**`B6=0x01 → Charging`（充电，高有效），`B6=0x00 → Discharging`（放电）**。

> 说明：第二次采集（135550）其实已经给出了这个方向（B6=01 在连接充电器窗口内），只是当时电量 90%+ 高位、幅度极小，与第三次采集（140047）观察到的方向互相矛盾，误判为「未验证」。真机实测最终裁定为第二次采集/实测的方向。

实现（`AusdomCodec.TryParse`）：短帧 `C4` 的 B6 `0x01→Charging`、`0x00→Discharging`、其它值 `Unknown`；长帧 `C6`（B6 是电量）与信息帧 `0x13`（无充电位）一律 `Unknown`。
