# CHERRY PIXIU75（dongle 046A:01E4 / 有线 046A:01E2）

> 从 [protocols.md](../protocols.md) 拆出（2026-10-21）。结论均来自真机验证或官方软件抓包；改协议代码前先读本文。

## 1. CHERRY PIXIU75 无线（dongle VID_046A&PID_01E4 / 有线 VID_046A&PID_01E2）—— ✅ 已打通，应用在用

### 1.1 接口地图

- 2.4G：dongle `046A:01E4`，产品名 `PIXIU75 Dongle`（蔚蓝档案 圣园未花联动款）。**键盘本体是 `046A:01E2`**，插 USB 线时直接以 `046A:01E2`「PIXIU 75」出现，dongle 随之消失。
- 块通道：`MI_01&Col04`，usage page `0xFF1C` / usage `0x0092`，输入输出均 **64 字节**，report ID `0x04`。**无线与有线是同一套块协议、同一个通道**，插件按通道特征匹配，换线不用改代码（有线时另多出 `MI_02` usage page `0xFFEF` 64B 双向集合，未使用）。
- 同一 dongle 的 keyboard（9B）、system control（2B）、consumer（3B）、mouse（8B，RID 6）、`0x0001/0x0000` 33B（RID 5）集合都没有电量字段；键盘/鼠标顶层集合普通进程 `CreateFile` 返回 err=5，别在上面耗时间。

### 1.2 帧格式（64 字节，report ID `0x04`）

| 偏移 | 含义 |
|---|---|
| `[0]` | report ID `0x04` |
| `[1..2]` | 令牌，LE16（真机与官方软件**恒为 0**，未验证其他值，插件只用 0） |
| `[3]` | 块号 |
| `[4]` | 本次读长度 |
| `[5..6]` | 块内偏移，LE16 |
| `[7]` | 保留 0 |
| `[8..]` | payload；不足 64 字节补零 |

应答原样回显令牌，payload 从 `[8]` 开始：

```
请求  04 00 00 1d 18 00 00 00 00...            ← 读块 0x1D，长 0x18
应答  04 00 00 1d 18 00 00 00 aa 55 00 00 6a 04 e2 01 01 00 01 00 01 00 ...
请求  04 00 00 1a 04 00 00 00 00...            ← 读块 0x1A（电量），长 4
应答  04 00 00 1a 04 00 00 00 30 00 00 00 ...  ← 0x30 = 48%
```

### 1.3 ⚠ 传输方式：只有 WriteFile 通

`HidD_SetOutputReport`（控制传输 SET_REPORT）**完全无应答**，抓 45 秒一帧不回；改用 `WriteFile`（中断 OUT 端点，句柄需 `GENERIC_READ|GENERIC_WRITE` + `FILE_FLAG_OVERLAPPED`）立刻有回应。VigilWatt 的 `HidDeviceHandle.WriteOutput` 走 `FileStream.WriteAsync` → `WriteFile`，正好是这个形态，无需另外包装 `SetOutputReport`。

### 1.4 块表（扫描 0x00–0x3F，offset 0、len 0x18）

| 块 | 内容 | 用途 |
|---|---|---|
| `0x1A` | 电量百分比 + 充电位 | **本应用只用这个**（见 13.5） |
| `0x1D` | `aa 55 00 00 6a 04 e2 01 …` = 签名 + VID + 键盘 PID | 认设备用，但**只在会话刚建立时给真值**，之后长期回全零（见 13.6） |
| `0x03` | `aa 55 00 00 06 80 08 00 … 0f 32`（0x16 处 3890，疑似 mV） | 未证实 |
| `0x05` / `0x06` | 同一份 `01 13 04 02 00 ff ff …`，随时间变化 | 未证实 |
| `0x07` / `0x08` | 键位映射表 | 不用 |
| `0x0a` | 灯效矩阵 | 不用 |
| `0x1b` | 索引表 | 不用 |
| 其余 | 全零 | — |

`0x22`/`0x23`/`0x24` 完全无回应。

### 1.5 电量与充电位

块 `0x1A`、offset 0、长度 4：

| payload 偏移 | 含义 |
|---|---|
| `[0]` | 电量百分比 `0..100` |
| `[1]` | **最低位 = 充电中**（`0x01` 充电 / `0x00` 放电），高 7 位保留 |
| `[2..3]` | 恒为 0，未证实 |

真机采样（2026-10-18，官方软件界面同步核对）：

```
放电  04 00 00 1a 04 00 00 00 30 00 00 00 …   ← 48%，官方软件显示 48%、电池无闪电
插线  31 01 00 00                              ← 49% + 充电位 1
随后  32 01 00 00 / 33 01 00 00                ← 50% / 51%，官方软件显示闪电 + 51%
应用  55% 充电=True                             ← 装机后日志 Charging=Charging
```

- 协议没有"充满"编码，`100% + 充电位=1` 按 `Charging` 报（与北通「满电」语义不同，别套 `>=100 && 未充电`）。
- 块 `0x1A` 也会**自发推送**（无需请求）：被动抓包见过 `04 00 00 1a 04 00 00 00 32 01 …`。
- 有线/无线两种接法读数一致，充电位只在真插线时变 1。

### 1.6 已知行为 / 坑

- **深度休眠时块通道完全静音**：键盘闲置一段时间后所有块请求超时（Python 与插件都复现），敲一下键盘即恢复。插件按"无应答"处理，不据此判离线（`Silence=Zero`、`CountPollFailures=false`）。
- **0x1D 不可靠**：会话刚建立时返回 `aa 55 …`，之后长期回 24 字节全零，故不是认设备的必要条件（插件只把它当附加校验，PID 读不到就记 `未公布`）。
- 官方 CHERRY Utility Software（`D:\Cherry\UtilitySoftware`）能同时连上并显示电量；它启动约 60 秒后自行退出，期间本插件读块仍正常。
- dongle 会话会被崩溃进程粘住（同 [mchose.md](mchose.md) §1.5）：读到超时先怀疑有残留进程占着句柄。
- **换接法会被当成两台设备**：2.4G 下产品名是 `PIXIU75 Dongle`、有线下是 `PIXIU 75`，显示名因此不同（`CHERRY PIXIU75` / `CHERRY PIXIU 75`），历史库里各占一行、互相显示"离线"。设备 ID 由路径/属性推出，协议层无法合并（见 BACKLOG CR-68）。
- 应用启动时若已有实例在跑，新进程记 `检测到已有实例运行，退出` 后退出——排查"改了 dll 没反应"务必先确认没有残留实例（单实例互斥，见 `src/VigilWatt.App/App.xaml.cs:151`）。

### 1.7 安全与开关

- 写入受 `PluginEnabled["Cherry"]` 控制，**默认关闭**（开插件即授权写帧，见 safety.md §3 规则 2）。
- 只发"读块"请求（块号 + 长度 + 偏移），不碰灯效、键位、配置写入；每帧都带块号校验，迟到的无关应答会被丢弃。
