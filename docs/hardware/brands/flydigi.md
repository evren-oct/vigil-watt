# 飞智 FLYDIGI 2.4G 电量（APEX5 / APEX6）

> APEX5 接收器 `VID_37D7&PID_2501`（产品串 `Flydigi APEX5 Wireless`），APEX6 接收器 `VID_37D7&PID_2502`（产品串 `Flydigi APEX 6`）。
> APEX5 的协议与样本来自贡献者 2026-10-19 的采集包（NewXInput 心跳，帧抄自官方 Space Station 的 `service_log`），
> **本仓库维护者没有 APEX5，未复测**；APEX6 由 2026-11-17 本机真机打通（型号 ID 150，与 XInput `full` 交叉一致）。
> 索引与其它设备见 [protocols.md](../protocols.md)。

## 1. 实测身份与认领判据

同一个 dongle 枚举出 5 个 HID collection，电量只走厂商协议集合。认领必须同时满足下表全部条件（`FlydigiCodec.IsSupportedInterface`）：

| 判据 | 取值 |
|---|---|
| VID / PID | `0x37D7` / `0x2501`（APEX5）或 `0x2502`（APEX6） |
| usage page / usage | `0xFFA0` / `0x0001` |
| 输入 / 输出报告长度 | APEX5 **32 / 32**、APEX6 **33 / 33**（含 report ID，本机实测）——两代长度不同，判据按 PID 分开卡 |
| 输出报告 ID | caps 给的值（APEX5 实测 `0x03`、APEX6 实测 `0x00`）；读不到时按 `0x03` 兜底，三种 ID 都能得到同一应答 |

⚠ **最容易踩的坑**：APEX6 是 33/33，若沿用 APEX5 的 32/32 严格判据，`IsCandidate` 会直接 false、插件完全不认领（日志里连查询都不会有）。2026-11-17 首次接入时踩过一次，单测 `InterfaceCriteria` 已把两代长度分别锁住。

同一 dongle 上另一个 `0xFFEE/0x0001` 集合（Output 12B）不承载电量，`0x0001/0x0005` 是标准 Gamepad、`0x0001/0x0002`、`0x0001/0x0006` 是鼠标/键盘——这些都不在判据里。

## 2. 心跳请求（32 字节）

```
03 5A A5 01 02 03 00 00 … 00
└┬┘ └┬┘ └┬┘ └┬┘ └┬┘
ID  帧头 cmd  长度 子命令
```

帧出自官方 `service_log` 原文，**一字未改**；插件只发这一条，不做命令枚举。写入走 `WriteOutput`（WriteFile）——这台 dongle 的写路径可用，不需要像 ATK 那样回落 `HidD_SetOutputReport`。两支合并时把兜底统一掉，见 BACKLOG CR-88。

## 3. 应答字节表

净载荷 31 字节，索引从 `0x5A` 起算（整帧绝对下标 = 本表 + 1）：

| idx | 值 | 说明 |
|---|---|---|
| 0–1 | `5A A5` | 帧头 |
| 2 | `01` | cmdId |
| 3 | `01` | 长度 |
| 4–10 | — | 固定（`00 80 02 00 00 00 00`，idx6 恒 `02`，别当电量） |
| **11** | **`02`–`05` / `11`** | **电量档位 0–5（×20 = 百分比）；`0x11` = 充电中，此时不含电量** |
| 12–14 | `45 01 00` | 固定 |
| 15–20 | — | 设备 MAC |
| 21–22 | `00 00` | 固定 |
| 23 | `01` | 恒为 `01`，一周日志没变过 —— **不是充电标志** |
| 24 | `28` | 恒为 40，**不是电量**（六天 13 次采样未变） |
| 25–30 | `00 00 11 31 1F 00` | 固定 |

**两个陷阱都写进单测**：idx24 的 `0x28` 看着像 40%，idx23 的 `0x01` 看着像充电位，实测都不是。

## 4. 档位与充电位

从官方 `service_log` 挖出 6 天内 13 次心跳应答，只有一个字节在变，单调递减 `05→04→03→02`，现场对照手柄屏幕约 40%，`2×20=40` 吻合。

**充电位 `0x11` 有实证**（2026-10-19 22:16 插线），三方互相印证：

1. **HID 直读**：插线后连续 47 次采样，idx11 恒为 `0x11`；与插线前的 `0x02` 帧逐字节比对，32 字节里只有 idx11 变；
2. **官方日志**：同一时刻 22:16:19 的 ack 也是 `…00-00-11-45-…`；
3. **XInput**：同时把电池类型切成 `WIRED`。

拔线立刻回落（22:02:19 实测 `0x11 → 0x02`），不需要等轮询周期。

**必须注意**：`0x11` 低 4 位是 `1`，看着像「1 档」，但那不是电量。按档位换算得 `17×20=340%`，按低 4 位换算得 20%，而实际电量是 40%——两种都错。插件的处理是**沿用上一次已采信的电量**、只把状态改成充电中；开机就在充电时没有基准，百分比显示 `—`、设备仍算在线（`NullPercentMeansOffline = false`）。

## 5. APEX6：按型号 ID 分档（0~10 档 ×10）

APEX5 与 APEX6 共用同一帧头 `5A A5`、同一个 `[11]` 字节位置，但**语义完全不同**，必须按报文里的型号 ID（`[5]`）分流，不能只看 PID：

| 型号 ID（`[5]`） | 型号（SDL 定义） | `[11]` 语义 |
|---|---|---|
| 128 / 129 / 133 / 134 | APEX5 | 低 4 位档位 0~5（×20），`0x11` 哨兵 = 充电中（不含电量） |
| 149 / 150 / 152 | APEX6 / Apex6 Pro / Apex6 Pro 幻影版 | 高 4 位充电状态 + 低 4 位档位 0~10（×10） |
| 130 | Vader5 Pro | 低 4 位档位 0~5（×20） |

APEX6 的 `[11]` 拆两半：**高 4 位** = 充电状态（`0` 放电 / `1` 充电中 / `2` 已充满），**低 4 位** = 档位 0~10，每档 10%。已充满（`2`）直接给 100%，不看档位残留。

真机样本（2026-11-17，`0x2502`）：

```text
5A A5 01 01 00 96 01 00 00 00 00 0A 45 …
             └┬┘           └┬┘
      [5]=0x96=150     [11]=0x0A → 状态0、档位10 → 100%
```

同一时刻 XInput 报 `BatteryType=wired`、`BatteryLevel=full`，两侧对「满电」一致。`[5]=150` 在 SDL 里是 **Apex6 Pro**，而产品串只写 `Flydigi APEX 6`——列表型号名以产品串为准，档位换算以 `[5]` 为准。**APEX6 普通版与 Pro 版协议不区分**（149/150/152 同家族、同 ×10）。

**为什么不能只看 PID**：APEX5 与 APEX6 分属 `0x2501` / `0x2502`，但 Vader5 Pro（`0x2401`，型号 ID 130）也同属 `37D7` 家族、共用 `0xFFA0` 接口——若只按 PID 判档，会把 Vader5 Pro 的 5 档当 10 档、读数翻倍。型号 ID 是唯一可靠判据；ID 为 0（没报）时才退回 PID 兜底。

## 6. 安全边界

- 只发这一条官方同款心跳，帧出自官方 `service_log`，符合 [safety.md](../safety.md) §3 规则 1「只发有出处的帧」；
- 会写帧，`PluginEnabled["Flydigi"]` 默认 **false**；
- 连续 3 次无应答 → 熔断停写 + 判离线，退避 30 秒起递增、封顶 5 分钟（基类统一机制）。

## 7. 未验证项

1. **接收器在位但手柄关机**、**手柄休眠**两态没单独测——只测到接收器被拔（`ReadFile` 报错、设备从 HID 列表消失）。所以现在"手柄关机"与"睡够 3 轮没应答"在界面上是同一种表现（转离线）。
2. **蓝牙模式（PID `0x1003`）**：接口是 BLE HID `0xFFA0/0x00FF`、25 字节，写入 report ID 是 `0x02`（用 `0x03` 会 `ERROR_INVALID_PARAMETER(87)`）。心跳 8/8 次都有应答，但应答第 7 字节是不是电量**没证实**（插充电线该字节不变，做不了对照），故按 PID 排除。
3. **档位粒度 20%**：一次掉两档（40 点）会被基类过滤器按"异常读数"压 5 分钟才采信。这是全仓统一口径，暂不为单台设备调。
4. **`0x52` 等其它 cmd 帧**的语义未知，插件一律丢弃。
5. **APEX6 充电中 / 已充满两种状态位**：按 SDL 定义实现（高 4 位 1/2）。本机 2026-11-17 16:30 的日志曾抓到一帧 `[11]=0x1A`（状态 1 充电中、档位 10）且 `[6]=0`（有线），但那是重写前的探测程序、且未做「插线前后」对照，故**不算完整的真机验证**；重写后的应用内尚未复现充电态，仍需插线各测一次。
6. **APEX6 有线（USB 线）模式**：未验证，`[6]` 连接类型未解释。
