# 黑爵 AK870 与雷神 ML903 NearLink Se

## 1. 范围与来源

2026-10-18 在用户实机上确认接收器连接。只适配下列 VID/PID 与接口，不推断其他同系列型号、蓝牙或有线模式。两个插件继承 BatteryPluginBase，默认关闭，开关控制写入；每轮一条已知查询，复用基类失败熔断与退避。由 KNA7022 完成键盘及鼠标实机验证。

| 设备 | 接口 | 查询依据 | 实机结果 |
|---|---|---|---|
| 黑爵 AK870 | 3151:4011，usage FFFF/2，feature 长度 65 | [sharkfin 协议文档](https://github.com/dniminenn/sharkfin/blob/master/docs/PROTOCOL.md) 的 ROYUAN F7 状态命令 | 41%，休眠时在线位变化，唤醒后恢复 |
| ML903 NearLink Se | 369B:0234，usage FFA0/2，input/output 长度 64，输出 ID A0 | [雷神官方下载中心](https://www.thunderobot.com/service/download) 的 TRM_App_ML903Nearlink.exe，静态分析 Iton_HIDMOU_Com_x86.dll | 35%，应用显示 iton-device-info |

鼠标官方 DLL SHA256：ED8D7469CA2C5D32465295C156DDF5D447F3D3CEFEB8CBE75A4EF61DE33C7772。只提取分析文件，没有安装或运行官方驱动。get_wireless_status 构造 50FF，get_device_info 构造 02，经统一十六进制发送器加 A0 report ID。前者不作为电量查询；最终插件只发送后者。官方 battery 字段标签为 0225；0226 是 workmode，不能解释为充电状态。本文记录协议事实，未复制厂商程序代码或二进制。

## 2. 帧约定

AK870：64 字节 feature payload：F7 00 00 00 00 00 00 08，其余零，SetFeature 自动添加 report ID 00。等待 100ms 后 GetFeature(0)。返回含 ID：00 00 29 00 00 01 01 01 60，后面补零。索引 2 是百分比，索引 4 为 0 表示在线；索引 7 的设备位必须含键盘。接受 HID API 的 64/65 字节结果，拒绝异常范围和错误字段。充电状态未知。

ML903：64 字节输出 A0 02，其余零。实机 64 字节输入如下（后面补零）：

```text
a1 02 04 01 11 02 11 e3 01 9b 36 02 13 31 32 33 34 35 36 02 25 23 02 26 01
```

按标签边界解析：0204 在此型号实机帧中长度 2，0211 长度 4，0213 长度 6，0225/0226 长度 1。官方 DLL 的另一帧分支存在不同长度，不能直接套用到此响应。0225 后的 23 是十六进制 35。禁止按任意字节搜索标签，防止序列字段误匹配；未知标签、重复电量、非零尾部、错误长度/ID 和越界读数均拒绝。充电状态未知。

## 3. 接口冲突与验证边界

迈从原候选规则接受任意 vendor 64/64 接口，能够抢先认领 ML903 并发送无关探测，导致雷神插件跳过。实机关闭迈从后，雷神立即被识别。2026-10-19 同步上游 46efacb 后，沿用 MchoseInterfaceClassifier 的 VID 白名单替代本地单型号排除，加入 369B:0234 与 3151:4011 不被迈从认领的回归测试。2026-10-18 的本地适配版在迈从保持开启时，同时认领鼠标 35% 与键盘 37%。此项只针对已确认设备，不扩展探测范围。

AjazzCodecTests、ThunderobotCodecTests 覆盖实机帧、边界、异常、嵌入标签及查询内容。尚未验证不同固件、插线充电，故不显示推测的充电状态。2026-10-19 补充实机验证：开机返回 27%；鼠标断电而接收器保留时，同一 A0 02 查询在 1.5 秒内无响应；重新开机后恢复 27%。

设置页遵循上游品牌约定：黑爵 / AJAZZ、雷神 / THUNDEROBOT；Name 与配置键仍为 Ajazz、Thunderobot，避免破坏现有开关、设备 ID 与历史。BuildDisplayName 保留具体型号用于扫描结果；后续同品牌型号扩展仍进入该品牌插件，不增加设置开关。
