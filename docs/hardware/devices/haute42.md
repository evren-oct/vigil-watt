# Haute42 Adapter 4DS（DualSense 适配器）

> 品牌是 **Haute42**（国产格斗外设，`haute42.cn`，与 COSMOX 共用官方账号），**不是索尼**。
> 这个适配器插上后会把自己枚举成一只 DualSense（`054C:0CE6`），只能靠读固件特征报告认出来。
> 协议由贡献者 kaniu 真机抓取；本仓库维护者没有这台设备，**未复测**。

## 1. 为什么会被当成索尼手柄

`HautePlugin.IsCandidate` 匹配的是 `054C:0CE6`——DualSense 的 VID/PID。适配器借用这套身份让主机/游戏直接认它，
所以**判据必须排除蓝牙路径**：

| 插件 | 认领的接口 |
|---|---|
| `Sony.DualSensePlugin` | 蓝牙路径（判据里要求含 `{00001124-0000-1000-8000-00805f9b34fb}`），读输入 report `0x31` |
| `HautePlugin` | **非**蓝牙路径 + `FeatureReportLength ≥ 14`，读 feature `0xF9` |

两条判据互补，同一时刻只有一边能认领，不会抢同一个接口。

## 2. 三个 feature 报告

| report | 用途 | 判据 |
|---|---|---|
| `0xF8` | 固件串 | ASCII 以 `Haute42 ` 开头才算本适配器（认领的最终依据） |
| `0xFA` | 芯片 ID（8 字节） | 全 `0x00` 或全 `0xFF` 视为无效；转成 `haute:chip-<hex>` 当设备 ID |
| `0xF9` | 电量状态 | 见下表 |

`0xF9` 状态帧（≥14 字节）：

| 偏移 | 含义 |
|---|---|
| `[12]` | 电量百分比；`0xFF` = 帧在但没有读数（不算 0%），>100 视为非本协议帧 |
| `[13]` 低 4 位 | `0` 放电 / 非 0 充电中 / `2` 已充满 |

## 3. 为什么用芯片 ID 当设备 ID

同一只适配器换 USB 口后，Windows 给的接口路径会变。用路径哈希当 ID 的话，换口就会在列表里多出一条"新设备"、
历史记录和自定义名称都断掉。`0xFA` 的芯片 ID 是机身身份，换口不变，所以 `BuildDeviceId` 覆写成 `haute:chip-…`。

这也意味着**读不到芯片 ID 时必须放弃这一轮认领**（而不是退回路径哈希）——否则同一个适配器会以两种 ID 交替出现。

## 4. 读失败后的自恢复

适配器偶发保留失效句柄（设备还在、句柄已废）。`PollDevice` 读失败时会重开一次句柄、复核固件串与芯片 ID：

- 芯片 ID 与当前设备一致 → 换掉旧句柄，继续读数；
- 芯片 ID 不一致 → 说明这个路径已经被另一只适配器占用，`RequestReprobe` 让下一轮重新认领，旧条目保持离线。

## 5. 安全边界

**零写入**：只发 `HidD_GetFeature`，不发任何 SetFeature / WriteOutput。`WritesEnabled` / `ProbeWrites` 都置 `false` 作纵深防御，
`SupportsFastDiscovery = true`（零写入才允许进 15 秒发现档）。

品牌开关 `PluginEnabled["Haute42Gaming"]` 默认关闭，见 [safety.md](../safety.md) §3.1。
