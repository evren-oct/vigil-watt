# ilovbee b98 键盘（`258A:01BB`）

> 2.4G 接收器，**纯被动零写入**：键盘主动推 20 字节状态帧，应用只读不写。
> 证据来自 issue [#68](https://github.com/evren-oct/vigil-watt/issues/68) 的采集包（VigilWatt 1.3.0，
> 15 条记录、0 错误，贡献者 Raven3000），2026-11-01 收进仓库。
> 代码：`Plugins/Ilovbee/IlovbeeCodec`、`Plugins/Ilovbee/IlovbeePlugin`。

## 1. 接口与帧

接收器 `VID_258A & PID_01BB`，厂商串 `SINOWEALTH`，产品串 `2.4G Wireless Receiver`（泛化名，
认不出型号）。`258A:01BB` 是 SINOWEALTH 通用 dongle 号段，**别按 VID/PID 认型号**——
真正的门禁是帧格式与校验和，别的品牌用同一颗 dongle 也过不了 `IlovbeeCodec.TryParse`。

### 1.1 接口地图

| 接口 | usage | 报文 | 说明 |
|---|---|---|---|
| `MI_01 Col01` | `0xFF02 / 0x0002` | 输入 20 / 输出 20 | **状态帧来源**，唯一厂商通道 |
| 其余集合 | 系统键 / 多媒体 / 鼠标 | — | 与电量无关 |

无 Feature 报文（`featureReportLength = 0`），也没有发过任何查询帧——电量全靠键盘主动推。

### 1.2 帧格式（20 字节，report ID `0x13`）

```text
13 0A 01 00 04 <事件> <数值> <标志> 00 00 … 00 <和校验>
```

| 偏移 | 含义 |
|---|---|
| 0 | report ID `0x13` |
| 1–4 | 固定 `0A 01 00 04` |
| 5 | 事件：`0x05` 电量上报 / `0x02` 开关机 |
| 6 | 电量 0–100；开关机帧 `00` = 关机、`01` = 开机 |
| 7 | `bit0` = 刚插上充电器（**事件位，不是状态位**，见 §1.4） |
| 8–18 | 恒为 0，未观察到变化 |
| 19 | 校验和 |

**校验和 = 前 19 字节按 8 位求和（report ID `0x13` 也计入）**。issue #68 的 15 帧逐条复算全部命中，
是这台设备最强的帧判据；校验不过一律丢弃。

真机样本：

```text
静置      13 0A 01 00 04 05 4B 10 … 82   → 75%
插线后    13 0A 01 00 04 05 4C 00 … 73   → 76%
插线瞬间  13 0A 01 00 04 05 64 01 … 8C   → 100% 但不可信，见 §1.4
关机      13 0A 01 00 04 02 00 … 24      → 关机，不是 0%
开机      13 0A 01 00 04 02 01 … 25      → 开机，不是 1%
```

### 1.3 关机帧与开机帧

`[5]=0x02` 时 `[6]` 只有 `00`/`01` 两个值，是**开关机状态而不是电量**。插件把关机帧直接判离线、
开机帧只翻正在线，两者都不产生电量读数——不这么做，关机瞬间会显示 0%、开机瞬间显示 1%。

### 1.4 `[7]` bit0 只在插入那一刻为 1

整段采集里 `bit0` 只在「插上充电器」后的第一条帧出现一次（`13 0A 01 00 04 05 64 01 …`），
2 秒后的下一条就回 `0x00`，而**拔掉充电器没有对应的事件帧**。因此：

- 无法据此维持充电状态 → 插件一律返回 `ChargingState.Unknown`，界面不显示充电图标；
- 该帧的 `[6]` 是占位值（实测 `0x64` = 100%，前后帧是 75%/76%），**不采信其电量**，沿用上次读数。

`[7]` 的 `bit4`（`0x10`）在 75%/50% 两帧出现过，含义未知，未使用。

⚠️ **帧形状与迈从 V1 / 狼蛛 F99 高度同构**（同为 `13 0A 01 00 04 05 <电量> <标志>`），但 `[7]` 语义不同：
那两家的 `bit4` 是「充电中」（`aula.md` §1.2），这里的 `bit4` 出现在**插充电器之前**的两帧里、
插上充电器反而变成 `bit0`。**不要照抄 AULA 的 `(flag & 0x10) != 0`**。

### 1.5 读数是电压法，会跳

同一段采集里 2 秒内出现 `75 → 50`，插充电器瞬间又出现 `100`，拔线后回到 `75`；
开关机之后从 `81` 一路回落到 `75`。这是电压换算成百分比的典型特征，**不是精确库仑计**。
插件不做特殊修正，交给基类 `BatteryReadingFilter` 的 20 pp 门限挡掉单次跳变。

## 2. 休眠与离线

采集包开头 105 秒零帧（键盘当时在休眠），按键后才开始推帧。故 `Offline.Silence` 取 **300 秒**：
阈值压太短会把「睡着」判成「拔了」；真正关机有 §1.3 的关机帧，不依赖沉默兜底。

## 3. 未验证

- **本机没有这台键盘**，全部结论来自一份采集包（一台设备、一个批次、一个固件版本）。
- **充电位**：`bit0` 只有一次样本，`[6]` 在插线帧是 100% 但实际 75%。要确定「充电中」能否显示，
  需要一份**插上充电器后静置 3 分钟**的采集，看 `bit0` 是否保持、`[6]` 是否爬升。
- **休眠阈值**：300 秒是照狼途 T98 的经验取的，这台设备真实休眠多久没测。
- 关机后 dongle 是否仍枚举、`0%` 是否真实存在，均无样本。
