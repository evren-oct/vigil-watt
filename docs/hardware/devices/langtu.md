# 狼途 LANGTU T98 / T87

> 两个型号、两套完全不同协议，共用「狼途 / LANGTU」品牌开关，代码同目录 `Plugins/Langtu/`。
> - **T98**（`1A2C:8FFF`）：纯被动零写入，键盘主动推状态帧。证据来自 issue [#40](https://github.com/evren-oct/vigil-watt/issues/40) 真机与官方抓包，2026-10-31 收进（贡献者 YyingnLL / haloneko）。
> - **T87**（`0C45:FEFE`）：主动写 GET_DEVICE_INFO，与前行者 X87 同号段按产品名分流。2026-11-17 本机真机打通（29% / 28% 放电）。

---

## 一、T98（`1A2C:8FFF`）

### 1. 接口与帧

接收器 `VID_1A2C & PID_8FFF`，厂商串 `Shinetek Technology`，产品串 `2.4 Wireless Device`（泛化名，
认不出型号）。官方驱动 `LANGTU T98 RGB` 只显示 4 格电量，没有百分比。

### 1.1 接口地图

| 接口 | usage | 报文 | 说明 |
|---|---|---|---|
| `MI_00` | `0xFF02 / 0x0002` | 输入 65 / 输出 65 | **状态帧来源**，唯一可读写通道 |
| `MI_03 Col05` | `0xFF01 / 0xFF01` | 输入 4 | 3 字节通知帧，实测全程静音 |
| `MI_03 Col02/03` | 系统键 / 多媒体 | 输入 2 / 3 | 与电量无关 |

官方 `config.xml` 声明 2.4G 走 `MI_03`，但该集合没有输出或 feature 报文，发不出查询。
**这台设备不需要查询**——状态帧由键盘主动推送，约 5.5 秒一条。

### 1.2 帧格式（65 字节，report ID 0）

有效内容只有前 8 字节，其余补零：

```text
00 AA 55 CC 33 0E <电量> 01 00 00 …
```

- `[1..2]` = `AA 55` 同步头，`[5]` = `0x0E` 命令字——**两者同时命中才算本协议帧**
- `[6]` = 电量（0–100）
- `0xFF` 是插拔充电线瞬间的「读数无效」哨兵，**必须丢弃**，否则会显示 255%

真机样本：

```text
静置      00 AA 55 CC 33 0E 4E 01 …   → 78%
插线后    00 AA 55 CC 33 0E 57 01 …   → 87%
插线瞬间  00 AA 55 CC 33 0E FF 01 …   → 丢弃
```

### 1.3 `[7]` 不是充电位

`[7]` 恒为 `0x01`，**插拔充电线都不变化**。因此插件一律返回 `ChargingState.Unknown`，
界面只显示电量、不显示充电图标——这一条在 issue #40 里已被明确证伪，不要再按 `[7]` 推断。

### 1.4 数值语义：电压换算，不是库仑计

| 时刻 | 读数 | 事件 |
|---|---|---|
| 静置 | 78，连续两分钟不变 | 基准值 |
| 插线 | 78 → 87，每 5.5 秒 +1 | 插线十几秒后开始爬升 |
| 插线 22 分钟后 | 92 | 进入慢速段，约 0.27%/分钟 |
| 拔线 | 87 → 78，3 分钟内衰减回稳 | 电压松弛特征 |

插电瞬间约 +10 的跳变、随后每分钟约 1 点的慢爬，符合**电压换算得到的百分比**特征。
充电期间虚高约 10 点，与厂商自带 4 格 UI 的数据源一致，**不能当作精确百分比**。

## 2. 休眠与离线

设备休眠时接口**完全静音**（实测连续 4 分钟零帧），按键后立即恢复。故插件的
`Offline.Silence` 取 **300 秒**——低于 4 分钟会把「睡着」判成「拔了」；真正关机才会无限静音，
5 分钟足够兜住。拔掉接收器时靠枚举移除判离线，不依赖沉默。

## 3. 未验证

- **只有一台设备、一个批次**，没有第二个固件版本样本；`0xFF` 哨兵只见过插拔瞬间一次。
- **0% 是否真实**：协议里 `0` 与 `0xFF` 都可能出现在异常态，但只确认了 `0xFF` 是哨兵，
  `0` 暂按真实电量处理（无样本）。
- `MI_03 Col05` 的 3 字节通知帧全程静音，**含义未知**，未接入。
- 长按关机、换电池、多台同型号同时插着均未测。

## 二、T87（`0C45:FEFE`）

> 主动写 GET_DEVICE_INFO（AULA 协议族），与前行者 X87 **同 VID/PID/usage/长度**、帧完全不同。
> 2026-11-17 本机真机打通。代码：`Plugins/Langtu/LangtuT87Codec`、`Plugins/Langtu/LangtuT87Plugin`。

### 1. 接口与认领

接收器 `VID_0C45&PID_FEFE`，产品串 `Langtu T87-2.4G`。本机厂商接口有两个：

| 接口 | usage | 报告长度 | 结论 |
|---|---|---|---|
| MI_03 | `0xFF60/0x0061` | IN 33 / OUT 33 | **唯一承载电量协议**，只写它 |
| MI_04 | `0xFF59/0x0061` | IN 65 / OUT 65 | 长度不符，写它必失败（同前行者 X87 的陷阱） |

键盘本体在应答里自报 `VID=0x0C45 / PID=0x8006`（payload `[4..7]` 小端），与 dongle 的 `FEFE` 不同——**认领不能用自报 PID**，只能用 dongle 的枚举信息。

### 1.1 与前行者 X87 的认领冲突

`0C45:FEFE` 上叠着两个品牌，指纹逐条相同（VID/PID、`0xFF60/0x0061`、33/33 字节），连 MI_04 陷阱都一样，但帧完全不同：

| 品牌 | 查询帧 | 本机应答 |
|---|---|---|
| 前行者 X87 | `00 20 01 …`（33B，[32] 校验和） | **无** |
| 狼途 T87 | `00 AA 10 18 …`（33B，GET_DEVICE_INFO） | ✅ 29% / 28% |

HID 层分不出品牌，唯一可用证据是产品名：`LangtuT87Plugin.IsCandidate` 要求产品串含 `langtu`，`EweadnPlugin.IsCandidate` 反向排除含 `langtu` 的接口，避免每 12 秒给狼途 dongle 白写一帧 X87 查询。

⚠ 已知边界：若某批次产品串为空或不含 `langtu`，两个插件都不会认领（前行者会认领并静默失败）。届时先看诊断页的产品串再决定扩展判据——不要为"认得出"放宽到"同 VID 就试"。

### 2. 协议：GET_DEVICE_INFO（cmd `0x10`）

#### 2.1 请求

33 字节 output report，首字节 report ID `0`：`00 AA 10 18 00 00 00 00 …`。`[3]` 写**本包**字节数（33 − report ID − 8 字节头 = 24），不是总长度 56——写 56 时 dongle 对三种命令全零应答，容易误判成"协议不对"。只发首包即可，电量字段在首包内。

#### 2.2 真机应答

```text
55 10 18 00 00 00 00 00 | 40 00 00 0C 45 0C 06 80 16 01 FF FF 09 00 03 00 02 1D 00 00 00 00 00 00
```

payload 偏移（以 `0x55` 为 0）：`[4..5]` 自报 VID `0x0C45`、`[6..7]` 自报 PID `0x8006`、`[16]` workMode=2（2.4G）、`[17]` 电量 29%、`[18]` 充电位 0。

#### 2.3 判据

- 帧头 `0x55` + cmd `0x10`，payload 至少 19 字节；带/不带 report ID 前缀两种布局都兼容。
- **自报 VID 必须等于 `0x0C45`**，否则整帧拒收（休眠占位帧 VID=0 也据此被挡）。
- **自报 PID 只记日志，不做白名单**：它随型号变（T87 是 `0x8006`），卡死等于挡同协议族其他型号。
- 充电位语义（`[18] != 0` ⇒ 充电中）来自同协议族 AULA 实现，**2026-11-17 本机插拔线已验证**：未充电恒 `0x00`、插线后恒 `0x01`，拔线立刻回落 `0x00`（见 §4）。
- `[16]` 只用于日志核对。

#### 2.4 型号名从哪来

电量帧里没有型号字符串，列表型号名取 USB 描述符产品串（`Langtu T87-2.4G` → `T87`）。取不到产品串只写品牌 `狼途`，**不猜型号**。

### 3. 休眠、离线与节拍

- 键盘休眠后 MI_03 直接沉默（不是回全零），唤醒后立刻恢复应答。
- 因此插件**不记失败、不熔断**（`CountPollFailures = false`）：计失败会把"睡醒后重新读到"挡到 5 分钟。
- 代价：休眠期间列表保留最后一次读数、不翻离线（与前行者同）。
- 每轮 1 条查询帧，跟随 60 秒主轮询；不进 15 秒发现节拍。

### 4. 验证范围

| 项目 | 状态 |
|---|---|
| 2.4G 放电读数 | ✅ 本机真机 29%、28%、27% |
| 应用内认领与轮询 | ✅ 插件级端到端跑通，连接徽标显示「2.4G」 |
| 充电中 | ✅ 本机真机（2026-11-17 插线）：`[18]=0x01`，界面显示充电中 |
| 满电（100%） | ❌ 无样本；插线只测了约 15 秒，未充到满 |
| 有线（USB 线）模式 | ❌ 未验证，`workMode` 只见过 2。⚠ 若有线形态自报 VID 不是 `0x0C45`，会被 §2.3 的 VID 校验拒收——先看日志里的自报 VID 再决定放宽 |
| 其他狼途型号 | ❌ 未验证，产品串只认 T87 |

**充电插拔真机序列**（2026-11-17 17:16，`app-2026-11-17.log`）：

```text
17:16:19  27% 充电=False   [18]=0x00   未充电
17:16:24  27% 充电=True    [18]=0x01   插线
17:16:25  28% 充电=True    [18]=0x01
17:16:27  30% 充电=True    [18]=0x01   电压法爬升
17:16:39  28% 充电=False   [18]=0x00   拔线回落
```

与 T98 的「电压换算」特征一致：插线后读数短时偏高、拔线 3 分钟内回落（T87 这次 15 秒就从 30 回到 28）。**充电位是独立字段，不是靠电量变化反推**。
