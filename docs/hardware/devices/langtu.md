# 狼途 LANGTU T98（`1A2C:8FFF`）

> 2.4G 接收器，**纯被动零写入**：键盘主动推状态帧，应用只读不写。
> 证据来自 issue [#40](https://github.com/evren-oct/vigil-watt/issues/40) 的真机实测与官方软件抓包，
> 2026-10-31 收进仓库（贡献者 YyingnLL / haloneko）。代码：`Plugins/Langtu/LangtuT98Codec`、
> `Plugins/Langtu/LangtuT98Plugin`。

## 1. 接口与帧

接收器 `VID_1A2C & PID_8FFF`，厂商串 `Shinetek Technology`，产品串 `2.4 Wireless Device`（泛化名，
认不出型号）。官方驱动 `LANGTU T98 RGB` 只显示 4 格电量，没有百分比。

### 1.1 接口地图

| 接口 | usage | 报文 | 说明 |
|---|---|---|---|
| `MI_00` | `0xFF02 / 0x0002` | 输入 65 / 输出 65 | **状态帧来源**，唯一可读写通道 |
| `MI_03 Col05` | `0xFF01 / 0xFF01` | 输入 4 | 3 字节通知帧，实测全程静音 |
| `MI_03 Col02/03` | 系统键 / 多媒体 | 输入 2 / 3 | 与电量无关 |

官方 `config.xml` 声明 2.4G 走 `MI_03`，但该集合没有输出或 feature 报文，发不出查询。
**这台设备不需要查询**——状态帧由键盘主动推送，约 5.5 秒一条。

### 1.2 帧格式（65 字节，report ID 0）

有效内容只有前 8 字节，其余补零：

```text
00 AA 55 CC 33 0E <电量> 01 00 00 …
```

- `[1..2]` = `AA 55` 同步头，`[5]` = `0x0E` 命令字——**两者同时命中才算本协议帧**
- `[6]` = 电量（0–100）
- `0xFF` 是插拔充电线瞬间的「读数无效」哨兵，**必须丢弃**，否则会显示 255%

真机样本：

```text
静置      00 AA 55 CC 33 0E 4E 01 …   → 78%
插线后    00 AA 55 CC 33 0E 57 01 …   → 87%
插线瞬间  00 AA 55 CC 33 0E FF 01 …   → 丢弃
```

### 1.3 `[7]` 不是充电位

`[7]` 恒为 `0x01`，**插拔充电线都不变化**。因此插件一律返回 `ChargingState.Unknown`，
界面只显示电量、不显示充电图标——这一条在 issue #40 里已被明确证伪，不要再按 `[7]` 推断。

### 1.4 数值语义：电压换算，不是库仑计

| 时刻 | 读数 | 事件 |
|---|---|---|
| 静置 | 78，连续两分钟不变 | 基准值 |
| 插线 | 78 → 87，每 5.5 秒 +1 | 插线十几秒后开始爬升 |
| 插线 22 分钟后 | 92 | 进入慢速段，约 0.27%/分钟 |
| 拔线 | 87 → 78，3 分钟内衰减回稳 | 电压松弛特征 |

插电瞬间约 +10 的跳变、随后每分钟约 1 点的慢爬，符合**电压换算得到的百分比**特征。
充电期间虚高约 10 点，与厂商自带 4 格 UI 的数据源一致，**不能当作精确百分比**。

## 2. 休眠与离线

设备休眠时接口**完全静音**（实测连续 4 分钟零帧），按键后立即恢复。故插件的
`Offline.Silence` 取 **300 秒**——低于 4 分钟会把「睡着」判成「拔了」；真正关机才会无限静音，
5 分钟足够兜住。拔掉接收器时靠枚举移除判离线，不依赖沉默。

## 3. 未验证

- **只有一台设备、一个批次**，没有第二个固件版本样本；`0xFF` 哨兵只见过插拔瞬间一次。
- **0% 是否真实**：协议里 `0` 与 `0xFF` 都可能出现在异常态，但只确认了 `0xFF` 是哨兵，
  `0` 暂按真实电量处理（无样本）。
- `MI_03 Col05` 的 3 字节通知帧全程静音，**含义未知**，未接入。
- 长按关机、换电池、多台同型号同时插着均未测。
