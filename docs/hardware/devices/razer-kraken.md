# 雷蛇 Kraken V4 耳机（接收器 `1532:056C`）

> 与 [razer.md](../brands/razer.md) 的经典 90 字节 feature 协议、[razer-headset.md](razer-headset.md) 的 PA 协议都不同：
> Kraken V4 走 64 字节 `0x02` 报告，电量与充电是**两条独立命令**，每轮只能发一条（帧限频）。
> 协议由贡献者 kaniu 从官方 Synapse 逆向 + 真机验证；本仓库维护者未复测。

## 1. 接口与判据

| 判据 | 取值 |
|---|---|
| VID:PID | `1532:056C`（接收器） |
| usage | `0xFF14` / `0x0001` |
| report ID | 输出 `0x02` |
| 长度 | 进/出各 64 字节 |

## 2. 帧

查询帧（64 字节，`[0]` = report ID）：

```
02 00 60 00 00 00 04 00 00 80 <cmd> 00 00 00 … <crc>
   └ 事务号 0x60        └ 长度 4      └ dongle 标志 0x80
```

命令：`0x21` = 读电量、`0x2A` = 读充电状态。请求方向 `0x00`、应答方向 `0x01`、成功状态 `0x02`。

应答载荷只有 1 字节（`[13]`）：电量命令给百分比（0~100），充电命令给 `0`/`1`。

**校验和是 XOR**：请求覆盖 `[0..61]`（官方 Synapse `_createDataSendGeneral` 从 0 起算），
应答从 `[1]` 起算（不含 report ID）——两边口径不同，这是最容易写错的地方。

## 3. 每轮只发一条

接收器对同一时刻的第二帧不应答，所以插件按设备**交替**：第 N 轮问电量、第 N+1 轮问充电，
读到电量时沿用上次的充电状态，读到充电时沿用上次的电量。见 `RazerKrakenPlugin._turns`。

充电标志：`1` = 充电中；`0` = 未充电（100% 时由 `ChargingStateMap` 收尾成"已充满"）。

## 4. 与其它雷蛇插件的关系

`RazerKrakenPlugin` 是独立插件类，但 `Name` 同为 `Razer`、共用「雷蛇 / RAZER」这一个开关，
设置页按 Name 去重后只出一行（`AGENTS.md` §9）。
