# 雷蛇 Viper V3 Pro SE

## 1. 支持范围与协议来源

仅匹配真机验证的 **Viper V3 Pro SE 无线接收器**：VID `1532`、PID `00DF`、
USB `MI_00`，usage page `0001` / usage `0002`，Feature 报告长度 **91**。
不认领 `MI_01`、键盘/consumer collection、普通 V3 Pro `00C1` 或有线版 `00DE`；
这些型号/模式没有在本次接入中验证。

公开协议依据是 OpenRazer 项目：

- [型号与等待时间](https://github.com/openrazer/openrazer/blob/master/driver/razermouse_driver.h)
- [型号对应的事务号、电量与充电查询](https://github.com/openrazer/openrazer/blob/master/driver/razermouse_driver.c)
- [查询命令](https://github.com/openrazer/openrazer/blob/master/driver/razerchromacommon.c)
- [报文结构](https://github.com/openrazer/openrazer/blob/master/driver/razercommon.h)
- [校验与控制传输](https://github.com/openrazer/openrazer/blob/master/driver/razercommon.c)

OpenRazer 驱动源文件声明 GPL-2.0-or-later；本接入依据协议事实和本机响应重新编写 C#，
未复制其驱动代码。公开实现支持不等于 VigilWatt 在所有固件或系统上均已验证。

## 2. 报文格式

下表偏移按 **90 字节协议载荷**计，不含 Windows Feature API 前置的 report ID `00`。
`HidDeviceHandle.SetFeature(0, payload)` 添加这一字节；`GetFeature(0)` 返回完整 91 字节报告。

| 字段 | 偏移 | 查询 / 响应 |
|---|---|---|
| 状态 | 0 | 查询 `00`；只接受成功响应 `02` |
| 事务号 | 1 | `1F` |
| 剩余包数、协议类型 | 2–4 | 全 `00` |
| 参数长度 | 5 | `02` |
| 命令类 | 6 | `07` |
| 命令 | 7 | `80` 读电量；`84` 读充电状态 |
| 返回值 | 9 | 电量 `00–FF`；充电 `00/01` |
| 校验 | 88 | 对载荷 [2, 88) 逐字节 XOR |
| 保留 | 89 | `00` |

发送后等 **60 ms** 再获取响应，依据该型号公开实现的约 59.9 ms 等待时间。
验证长度、report ID、成功状态、事务号、命令、参数长度、包数、协议类型、校验和保留位后才采信。
充电字段只接受 0/1；未知值不会当成“未充电”。

电量按 `(raw * 100 + 127) / 255` 取最近整数百分比。
本型号允许真实的 0/1%，通过插件覆写读数下界实现，不改变其他品牌过滤策略。

2026-10-24 独立探针实测：电量值 `9C`（156/255，约 61.18%），
两次一致；充电值 `00`，未充电。响应头为：
`00 02 1F 00 00 00 02 07 80 00 9C`（含 report ID），校验字节 `19`；
充电响应头 `00 02 1F 00 00 00 02 07 84 00 00`，校验 `81`。

## 3. Windows 接口与轮询

该通道位于受系统保护的鼠标 collection，不能要求普通输入读写权限。

- 扫描阶段只读元数据，`CreateFile` 使用 desired access 0。
- 插件覆写 `FeatureOnly`，只持有零访问权限的 SafeFileHandle；不创建输入 FileStream，
  不读取移动、按键或键盘输入，也不发送 output 报告。
- 其他插件默认仍使用原来的异步读写句柄。
- 每次 Probe/Poll 最多发送一条查询。首次只读电量，充电状态显示 Unknown；
  此后按 60 秒轮询交替读充电、电量，两类数据各约 120 秒刷新。
- 充电回复沿用最近一次验证过的电量。查询失败清除缓存充电状态，并让下轮优先读电量。
- 开启 15 秒发现探测，失败冷却 8 秒；仅尚未认领的接口会发送已知电量查询，已认领接口在发现路径不发帧。
- 采用基类认领、黑名单、移除释放和异常过滤；插件按实际查询结果记失败账。
  连续 3 次失败熔断并标离线，按基类递增退避恢复；收到有效应答清零失败与退避。
- 查询状态由句柄弱关联持有，释放/重认领时不沿用旧设备的充电缓存。

## 4. 开关与验证边界

设置页品牌名为「雷蛇 / Razer」，默认关闭。
`AppSettings.PluginEnabled["Razer"]` 是唯一写入开关，查询发送点再次检查；
只允许构造已知的 `07/80` 与 `07/84` 查询，不发送配置、配对或固件命令。

实机验证（2026-10-24/25）：无线模式电量 61%（后续 58%），充电状态 Discharging。
实际扫描器可枚举受保护接口；默认关闭不认领，启用后认领、交替轮询、
独立 SQLite 历史写入/读回与 Detach 释放均通过。短时查询期间雷云保持运行。
纯逻辑测试覆盖协议样本、损坏帧、接口匹配、查询状态、Feature 句柄和低电量边界。

尚未实测：插线充电切换、有线模式、物理拔插、自然休眠唤醒、低电量、
长时间与雷云并行运行。单测覆盖的边界值或失败帧不代表这些硬件场景已经实测。

## 5. 开机首次识别失败后的自动恢复

雷蛇插件参与后台 15 秒发现节拍，未认领接口探测失败后冷却 10 秒；
下一发现节拍可再次尝试，不依赖主窗口打开或手动刷新。
已经认领的接口在发现路径直接返回缓存状态，不额外查询电量；正常主轮询仍为 60 秒。
插件默认关闭、查询授权、已认领设备的失败熔断和退避沿用基类。

隔离验证使用普通临时文件模拟首次探测失败，确认发现会调度雷蛇、立即重试被冷却阻止、
11 秒后恢复探测资格、失败后释放认领；该调度验证没有访问真实硬件。
尚未通过实际重启电脑验证冷启动，模拟调度不等同于真实开机验收。
构建与改动范围检查见 [适配审查](../../reviews/archive/2026-10-25-asus-razer-adaptation-review.md)。
