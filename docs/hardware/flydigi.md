# 飞智 FLYDIGI APEX5 2.4G 电量

> 接收器 `VID_37D7&PID_2501`（产品串 `Flydigi APEX5 Wireless`）。
> 协议与样本来自贡献者 2026-10-19 的采集包（NewXInput 心跳，帧抄自官方 Space Station 的 `service_log`），
> **本仓库维护者没有这台设备，未复测**。索引与其它设备见 [protocols.md](protocols.md)。

## 1. 实测身份与认领判据

同一个 dongle 枚举出 5 个 HID collection，电量只走厂商协议集合。认领必须同时满足下表全部条件（`FlydigiCodec.IsSupportedInterface`）：

| 判据 | 取值 |
|---|---|
| VID / PID | `0x37D7` / `0x2501` |
| usage page / usage | `0xFFA0` / `0x0001` |
| 输入 / 输出报告长度 | 32 / 32（含 report ID） |
| 输出报告 ID | caps 给的 `0x03`（读不到时按 `0x03` 兜底） |

同一 dongle 上另一个 `0xFFEE/0x0001` 集合（Output 12B）不承载电量，`0x0001/0x0005` 是标准 Gamepad、`0x0001/0x0002`、`0x0001/0x0006` 是鼠标/键盘——这些都不在判据里。

## 2. 心跳请求（32 字节）

```
03 5A A5 01 02 03 00 00 … 00
└┬┘ └┬┘ └┬┘ └┬┘ └┬┘
ID  帧头 cmd  长度 子命令
```

帧出自官方 `service_log` 原文，**一字未改**；插件只发这一条，不做命令枚举。写入走 `WriteOutput`（WriteFile）——这台 dongle 的写路径可用，不需要像 ATK 那样回落 `HidD_SetOutputReport`。两支合并时把兜底统一掉，见 BACKLOG CR-88。

## 3. 应答字节表

净载荷 31 字节，索引从 `0x5A` 起算（整帧绝对下标 = 本表 + 1）：

| idx | 值 | 说明 |
|---|---|---|
| 0–1 | `5A A5` | 帧头 |
| 2 | `01` | cmdId |
| 3 | `01` | 长度 |
| 4–10 | — | 固定（`00 80 02 00 00 00 00`，idx6 恒 `02`，别当电量） |
| **11** | **`02`–`05` / `11`** | **电量档位 0–5（×20 = 百分比）；`0x11` = 充电中，此时不含电量** |
| 12–14 | `45 01 00` | 固定 |
| 15–20 | — | 设备 MAC |
| 21–22 | `00 00` | 固定 |
| 23 | `01` | 恒为 `01`，一周日志没变过 —— **不是充电标志** |
| 24 | `28` | 恒为 40，**不是电量**（六天 13 次采样未变） |
| 25–30 | `00 00 11 31 1F 00` | 固定 |

**两个陷阱都写进单测**：idx24 的 `0x28` 看着像 40%，idx23 的 `0x01` 看着像充电位，实测都不是。

## 4. 档位与充电位

从官方 `service_log` 挖出 6 天内 13 次心跳应答，只有一个字节在变，单调递减 `05→04→03→02`，现场对照手柄屏幕约 40%，`2×20=40` 吻合。

**充电位 `0x11` 有实证**（2026-10-19 22:16 插线），三方互相印证：

1. **HID 直读**：插线后连续 47 次采样，idx11 恒为 `0x11`；与插线前的 `0x02` 帧逐字节比对，32 字节里只有 idx11 变；
2. **官方日志**：同一时刻 22:16:19 的 ack 也是 `…00-00-11-45-…`；
3. **XInput**：同时把电池类型切成 `WIRED`。

拔线立刻回落（22:02:19 实测 `0x11 → 0x02`），不需要等轮询周期。

**必须注意**：`0x11` 低 4 位是 `1`，看着像「1 档」，但那不是电量。按档位换算得 `17×20=340%`，按低 4 位换算得 20%，而实际电量是 40%——两种都错。插件的处理是**沿用上一次已采信的电量**、只把状态改成充电中；开机就在充电时没有基准，百分比显示 `—`、设备仍算在线（`NullPercentMeansOffline = false`）。

## 5. 安全边界

- 只发这一条官方同款心跳，帧出自官方 `service_log`，符合 [safety.md](safety.md) §3 规则 1「只发有出处的帧」；
- 会写帧，`PluginEnabled["Flydigi"]` 默认 **false**；
- 连续 3 次无应答 → 熔断停写 + 判离线，退避 30 秒起递增、封顶 5 分钟（基类统一机制）。

## 6. 未验证项

1. **接收器在位但手柄关机**、**手柄休眠**两态没单独测——只测到接收器被拔（`ReadFile` 报错、设备从 HID 列表消失）。所以现在"手柄关机"与"睡够 3 轮没应答"在界面上是同一种表现（转离线）。
2. **蓝牙模式（PID `0x1003`）**：接口是 BLE HID `0xFFA0/0x00FF`、25 字节，写入 report ID 是 `0x02`（用 `0x03` 会 `ERROR_INVALID_PARAMETER(87)`）。心跳 8/8 次都有应答，但应答第 7 字节是不是电量**没证实**（插充电线该字节不变，做不了对照），故按 PID 排除。
3. **档位粒度 20%**：一次掉两档（40 点）会被基类过滤器按"异常读数"压 5 分钟才采信。这是全仓统一口径，暂不为单台设备调。
4. **`0x52` 等其它 cmd 帧**的语义未知，插件一律丢弃。
