# VGN 蜻蜓（Dragonfly）2.4G

> 两个世代、两套协议、两个号段：F1 V5 走 VGN 自家 `0x391D` 的 `kc2` 配置帧，F2 大师+ 走 Compx 号段 `0x3554` 的 `y2` 电量查询。
> 结论来自官方前端 bundle 与真机验证；改协议代码前先读本文。共用号段的陷阱见 [protocols.md](protocols.md) §2。

## 1. F1 V5 Turbo+（`kc2`）

### 1.1 接口与来源

官方网页驱动 `hub.vgnlab.com.cn` 的前端 bundle：设备表 `{vendorId:14621, productId:6691/4134, usagePage:65473, usage:1, customDeviceType:"vgn-kc2"}`，
控制器 `serveProvider:"kcMs2"`、`reportId=179(0xB3)`。本机在 `391D:1A23`（2.4G dongle）与 `391D:1026`（插线）上验证。

厂商接口 `usagePage 0xFFC1 / usage 0x0001`，进/出各 64 字节。

### 1.2 帧

WebHID 数据层 63 字节、**无校验字节**（官方驱动 `sendHidBuffer` 直接 sendReport）：

```
[0]=命令(0x06)  [1..62]=0
```

Windows 的 WriteFile 缓冲首字节是 report ID，故缓冲 64 字节、数据层整体右移一位：`buf[0]=0xB3 buf[1]=0x06 …`。

应答是"配置帧"（命令回显 `payload[0]==0x06`），电量不占独立命令，打包在其中：

```
payload[19]  bit0-6 = 电量 %   bit7 = 充电中
```

真机样本（插线充电中）：

```
B4 06 00 20 20 60 90 01 20 03 40 06 80 0C 00 19 01 06 00 05 A4 50 C3 ...
│  └ 命令回显                              └ payload[19]=0xA4 → 36% 且 bit7=1 充电
└ 应答 report ID (0xB4)
```

这一帧是"设备配置"整帧（回报率、灯效、`payload[20..21]=50 C3` 等数值都在），只有 `payload[19]` 的语义能直接对上官方驱动源码，所以只取它。
同一只鼠标另有一个可写 report ID `0xB5`（真机实测同样可用），插件按 0xB3 → 0xB5 顺序试，写失败即换下一个。

### 1.3 验证边界

同一只鼠标插线后会换 PID（`1A23` → `1026`）并少掉那个 33 字节接口，**两个 PID 都要认**，否则充电期间设备会从列表里消失。
本机验证到电量与充电位；不同固件、其它蜻蜓型号未验证。

## 2. F2 大师+（`y2`）

### 2.1 接口与来源

官方 VGN VHUB（Electron）`app.asar` 里的 `JmServe` 类：设备表 `{vendorId:13652, productId:64342, path:"mi_01&col05", customDeviceType:"vgn-y2", reportId:8}`。
本机在 `3554:FB56`（自报 `Dragonfly F2 Master+`，厂商串 `Compx`）上验证。

**这颗 dongle 不是 `0x391D`**——`0x3554` 是 Compx 共用号段，狼蛛 F99 Pro（`3554:FA09`）也在这段里，
所以不能按 VID 认领，必须带 usage 与长度：`0xFF02 / 0x0002`，17 字节双向，report ID 固定 `0x08`（写别的 ID 会被驱动直接拒）。

### 2.2 帧

payload 16 字节，report ID `0x08`，Windows 侧缓冲 17 字节：

```
[0]=命令  [1..14]=参数/数据  [15]=校验
crc = (85 - sum(payload[0..14])) & 0xFF
payload[15] = (crc - reportId) & 0xFF
```

应答（WebHID 的 data 不含 report ID，Windows `ReadInput` 含，前者即后者去掉首字节）：

```
[0]=命令回显  [1]=0 表示成功  [5]=电量%  [6]=1 表示充电中  [7..8]=电压 mV（大端）
```

真机样本（2026-10-21 本机，未插线）：

```
发 08 04 00 00 00 00 00 00 00 00 00 00 00 00 00 00 49
收 08 04 00 00 00 02 50 00 0F C8 00 00 00 00 00 00 20
    └ 命令回显        └ [5]=0x50=80%  └ [6]=0 未充电  └ 0x0FC8=4040mV
```

同一次会话里 `DeviceOnLine(0x03)` 的应答 `08 03 00 00 00 01 01 35 D9 …` 电量位不在同一下标，
所以解析必须卡命令回显，不能只认长度。

### 2.3 验证边界

有线形态 `3554:FB57` 来自 VHUB 设备表，同族同协议，**本机未复测**；低电量、充电切换未验证。

## 3. V98 Pro 键盘（`320F:5088`）—— 贡献者声明，本机未复测

厂商集合 `0xFF1C / 0x0092`，输出 ≥17 字节；键盘不发心跳，必须主动查。

```
发  04 00 00 1A 06 00 00 00 …        # report ID 0x04 + 7 字节查询帧，无校验
收  04 …  [3]=0x1A（电量帧标志）  [8]=电量%  [9]=充电标志
```

回包里 `[3] != 0x1A` 的一律丢弃——命令回显、灯效/键位数据都会落到同一接口。
会写帧，与蜻蜓共用 `PluginEnabled["Vgn"]`、默认关，只在 60 秒主轮询里查。

## 4. 插线后的双接口去重

同一只鼠标插线时接收器与本体两条接口同时在场，两条都认领会变成两行互相矛盾的读数（一行充电中、一行还是插线前的旧电量）。
`VgnDevicePairing.WirelessPathsToSkip` 按**序列号**配对（同一只设备的两条接口报同一个 SN），只保留插线那条——只有它带充电状态；
用户真有两台同型号鼠标时 SN 不同，不会被误合并。基类通过 `SkipPathsForThisPass` 钩子把这些路径从本轮摘掉。

## 5. 写入与开关

两套协议都要写帧（kc2 发配置帧、y2 发 `BatteryLevel` 查询），所以品牌开关 `PluginEnabled["Vgn"]` **默认关闭**，
插件开关即写入授权（见 [safety.md](safety.md) §3.1）。y2 的 15 秒发现节拍由 `ProbeCooldown = 20 秒` 兜住，
睡着时不会被反复戳；kc2 只走 60 秒主轮询。

## 6. F503 接收器接入调查（2026-11-03）

实测型号为 VGN F1 Pro，接收器 `3554:F503`，厂商接口 `MI_01/Col05`，usage `FF02/0002`，IN/OUT 均为 17 字节。
官方 `drive.vgnlab.com.cn` 设备表将其归为 `vgn-f1-pm`。
`scripts/probe-vgn-f503.py --query` 只发一次官方 BatteryLevel 查询，得到：

```text
发 08 04 00 00 00 00 00 00 00 00 00 00 00 00 00 00 49
收 08 04 00 00 00 02 5F 00 10 05 00 00 00 00 00 00 D3
```

命令回显、成功位和校验和均符合 §2：原始电量 95%、充电标志 0、电压 4101 mV。
无线电量查询与应用内显示均已确认；尚未对照官方 UI 百分比，未验证充电切换、有线 PID 或休眠唤醒。

适配前 `VgnY2Codec.IsMatch` 仅允许 `FB56/FB57`，所以 F503 在发查询前就被排除。
该白名单从引入提交 `afb7687` 起如此；注释说明 `3554` 是多品牌共用 VID，必须精确限制 PID、usage 和帧长。
已查看的提交和协议文档没有记载 F503 不兼容；当前属于尚未纳入匹配范围，而非实测失败后禁用。
现已增加 F503 精确匹配，并用上述真实回包补回归测试，沿用默认关闭的 VGN 品牌开关和现有查询路径。
只新增接收器 PID；有线 PID 与序列号配对尚未核实，不纳入双接口去重表。显示名沿用设备产品串，缺失时为“VGN 鼠标”。
