# 产品图远端化与按需下载（方案）

> **状态：未实施。** 当前仍是全内置（198 型号 / 337 张 / 11.75 MB），接入方式见
> [device-images.md](device-images.md)。本文只记录目标方案与已拍板的决策；
> 实施前先读第 5 节，不要凭本文直接改代码。
>
> 对应待办：`docs/reviews/BACKLOG.md` CR-162。

## 0. 一句话

manifest 全内置，PNG 放远端对象存储；用户第一次打开某台设备的详情页时，只下载这一张。

## 1. 为什么

| 项 | 现在 |
|---|---|
| 图片 | 337 张 / 11.75 MB |
| manifest | 198 个 / 146 KB |
| 占全量安装包 | **33%**（36 MB） |

- 用户通常只有 1~3 台设备，却要背全部型号的图；
- 每加一个品牌，所有用户的安装包都跟着变大；
- 仓库与安装包同步膨胀，发版要带全部历史资产。

## 2. manifest 为什么不远端化

198 个 manifest 一共只有 **146 KB**，内置成本可以忽略，但换来一个关键能力：
**离线时能区分「这台设备没图」和「这台设备有图但没下载」**。

如果 manifest 也远端取，没网时程序不知道 G502 到底有没有图，只能一律回退几何图标，
用户会误以为「不支持我的设备」。

**结论：只把 PNG 放远端，manifest 全内置。**

## 3. 数据流

1. 启动 → 加载内置 manifest（全量，零网络）；
2. 设备上线 → 按显示名 / VID+PID 匹配 → 得到 `品牌 / 型号 / 文件名`；
3. 查缓存 `<数据根>\device-images-cache\<品牌>\<型号>\<文件>`；
   - 命中 → 直接显示，不发请求；
   - 未命中 → 走第 4 步；
4. 拼 URL → 下载 → 校验文件头 → 写缓存 → 显示；
5. 任一步失败 → 静默回退 `DeviceIconFactory` 的几何图标，不弹错、不阻塞界面。

## 4. URL 规则：不需要索引文件

manifest 里已经带齐 `brand` / `model` / `colors[].thumbnail`，远端目录结构与仓库保持一致，
URL 直接拼出来：

```
<base>/device-images/<brand>/<model>/<file>
```

例：`<base>/device-images/logitech/MX_Master_3S/mx_master_3s.png`

**不需要额外维护一份「型号 → URL」的索引 JSON**，也就没有索引与资产不同步的风险。

## 5. 已拍板的决策

| 决策 | 结论 | 理由 |
|---|---|---|
| manifest | 全内置 | 146 KB；换来离线可判断「有图没下」 |
| 内置图片 | **一张不带** | 图是锦上添花，没图有几何图标；「常用 Top N」靠猜，猜错照样白占体积 |
| 下载时机 | 详情页首次打开时 | 后台预热会白下用户根本不看的型号，还要启动即联网 |
| 缓存淘汰 | 不自动淘汰 | 全量缓存也就 11 MB，不值得做 LRU |
| 清理入口 | 设置页手动「清空产品图缓存」 | |
| 换图失效 | **不做 per-file hash** | 换图可能性不大；真要换，清缓存即可 |
| 缓存目录 | 独立 `device-images-cache\` | 与用户自定义的 `device-images\` 分开，否则下载会覆盖用户自己的图、清缓存会误删 |
| 读取顺序 | 用户自定义 > 下载缓存 > 项目内置 | 复用现有两级，中间加一层 |
| 文件校验 | 文件头魔数（PNG / JPEG / WebP） | 防止 CDN 返回 404 页面被当成图；与导入脚本的 `is_image` 同规则 |

## 6. 待定

- **托管方**：Cloudflare R2（公开读 + 免费额度够个人用）或其它。要先确认国内可达性。
- **联网开关默认值**：倾向默认开（否则功能白做），设置页可关，关掉后只用本地已有图。
- **是否加「图未下载」提示**：倾向不加，静默回退几何图标即可。

## 8. 验收标准

- [ ] 全新安装后 manifest 齐全、PNG 一张不在；
- [ ] 打开详情页 → 下载 → 显示；再次打开不重复下载；
- [ ] 断网 → 回退几何图标，无报错、无卡顿、无弹窗；
- [ ] 缓存命中时不发任何网络请求；
- [ ] 设置页可关闭联网、可清空缓存，关闭后行为与当前版本一致；
- [ ] 列表、托盘、任务栏贴片、桌面小组件行为不变（它们本来就不用产品图）。

## 9. 明确不做

- **per-file hash 失效**：换图可能性不大，真要换就清缓存（用户 2026-11-13 判断）；
- LRU 自动淘汰；
- 后台预热下载；
- 多 CDN 回退（先单源 + 超时）。

## 10. 与「资产移出仓库」的关系

| 方案 | 仓库 | 安装包 | 改运行时 | 联网 |
|---|---|---|---|---|
| 现状 | 11.75 MB | 36 MB | — | 否 |
| A. 只移出仓库 | ~0 | 36 MB | 否 | 否 |
| **B. 按需下载（本文）** | ~0 | **~24 MB** | 是 | 是 |

A 是 B 的前置步骤：先把资产从 git 里挪走（`.gitignore` + 构建时下载再打包），
仓库立刻瘦身，代码一行不改；B 在此基础上再把运行时改成按需下载。

## 11. 风险

- **国内可达性**：Cloudflare R2 的公开域名在部分地区不稳。必须有超时与静默降级，
  参考项目已有的「GitHub 8 秒不通回退 Gitee」策略。
- **版权**：这些是厂商渲染图。现在已在公开仓库里分发，改到公开图床性质变化不大，
  但商用仍需重新评估（见 `device-images.md` §10）。
- **首次体验**：新装用户第一次打开详情页前没有产品图，可能误以为不支持设备。
