## 3. 修正与遗漏复核

普通中断输入未读到 N9 状态，故使用已验证的 `HidD_GetInputReport` 控制入口；没有修改其它插件的输入路径。该 API 本身不保证消费队列：空闲态是否能出现必须由 N9 实测支持。读取严格使用有效片段长度，长度 0 时忽略旧缓存；未确认空闲态时不得写入，重复快照不得向消息流二次追加。

排空不能阻止尚未到达的结果；本轮 ACK 是采纳异步电量的必要条件。按消息顺序处理同一报告，不能因为报告后面有 ACK 就接受其前面的旧结果。成功日志只记录命中的电量消息，避免输出可能含配对信息的旧缓存。

## 4. 未能证实

主界面显示、长期运行、电量自然下降、官方 App 对照、关机和重新接收行为均未实测；充电测试明确取消。Windows 单次 HID 控制调用使用原生超时，窗口约束查询循环，不保证打断正在进行的系统调用。不能把短时真机成功推广到其它 AKG 型号、固件或连接方式。

固定协议没有逐轮事务号，因此不能保证区分新 ACK 之后到达的旧结果；连续相同片段也可能与重复状态无法区分。重复过滤保持失败时不报电量的边界，不声称提供无损通知流。
