# HERO 68 Air 适配审查

## 1. 基线与边界

基线 `d434f90f6be61a28a0dc91c693c410e08964fac4`。改动范围为狼蛛插件、独立编解码/分片重组、相关测试和文档；未改 UI、版本号或安装包。

已向贡献者的 `372E:106C` 接收器发送官方固定 UUID / 电量查询及其分片 ACK；未发送配置命令。通过独立测试入口调用**实际 `AulaPlugin`**，使用隔离数据目录，未启动完整 WinUI 应用。真机为 10% 放电、接线保持 2.4G 后 10% 充电；认领、后续轮询、关品牌开关、释放句柄均执行过。

## 2. 逐条发现

- R1：HERO 每个输出片和 ACK 都检查 `WritesEnabled` 及完整接口指纹，复用默认关闭的 `Aula` 开关。单次查询只有一个已知命令，分片不能变成命令/ID 枚举。每轮最多 15 条输入 ACK，无超时重发。
- R2 / R4：沿用 `BatteryPluginBase` 的认领、释放、三次失败熔断及递增退避。每句柄传输状态由弱键表管理，不另外开启后台线程、定时器或句柄。
- R3：传输状态由基类现有 `IoGate` 串行保护；设备状态和历史记录通路没有新增共享对象。
- R5：查询失败保留 WARN；原始收发帧为 Debug，成功业务响应为 Info。
- R7 / R8：业务与分片逻辑零 WinRT 依赖，测试项目直接链接实际源码。25 项狼蛛相关测试通过，含 F99 Pro 既有 7 项；覆盖真实放电/充电帧、共享接收器型号排除、CRC、ACK、重传、乱序、截断、容量上界、循环序号及异步通知排除。解决方案构建 0 警告、0 错误。
- **既有 P1：休眠静音后按查询失败退避**。HERO 的无响应也能用 Python 复现，按键唤醒后不改帧即恢复。该类别已记录 CR-81，本轮补充 HERO 证据，没有绕过熔断来掩盖它。

## 3. 修正与遗漏复核

`372E:106C` 是共享接收器，必须取得 `12000000000A` 才命名为 HERO 68 Air；其他 UUID 不发后续电量查询。无线层的 `FE 05` 通知可能穿插在命令 ACK 之间，必须 ACK 并继续等待匹配响应。F99 Pro 的探测继续走基类线程池封装，避免新增异步覆写让它的同步等待堵住发现调用方。

## 4. 未证实部分

满电/中间电量、不同固件、实际休眠至恢复的时长、接收器拔插尚未真机复测。充满状态取官方标志语义并有合成向量测试，不能描述成已真机测得。USB 与蓝牙不在此次支持范围。没有对完整 UI、历史采样周期或安装包做验收。
