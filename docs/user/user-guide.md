# 使用说明

> 面向使用者：每个页面、每个开关是做什么的。开发相关看 [../dev/build.md](../dev/build.md)，
> 遇到异常先查 [../README.md](../README.md) 的「症状速查」。
> 本文只描述**当前版本已实现**的行为；标了「未验证」的功能以界面实际表现为准。

## 1. 它做什么，不做什么

**做**：读蓝牙设备（BLE GATT 电池服务、经典蓝牙 HFP 网关节点）、已适配的 2.4G 键鼠手柄电量、可选的本机电池；在托盘、设备列表、桌面小组件和任务栏贴片里显示；存历史并提供 24 小时 / 7 天 / 30 天统计。

**不做**：不改设备任何配置（DPI、回报率、灯光、宏一律不碰），不做游戏内叠加显示，不开 HTTP 接口，不联网上传数据。所有数据只在本机。

## 2. 第一次启动

1. 安装版装完、便携版解压后直接运行，**无需另外安装 .NET 运行时**。
2. 启动后不会弹主窗口，先到任务栏通知区域找 VigilWatt 图标；**首次可能收在 `^` 溢出区里**。
3. **左键**点图标打开主窗口，**右键**点图标出菜单。

托盘右键菜单只有三项：`打开主窗口`、中间是当前所有设备的电量只读列表（离线设备显示「离线」并置灰）、`退出`。

如果托盘里找不到图标，多半是 exe 被工作区的 Low 完整性标签带跑了——那是开发构建的问题，见 [../dev/runtime-pitfalls.md](../dev/runtime-pitfalls.md) §20。

## 3. 主窗口五个页面

| 页面 | 用途 |
|---|---|
| 设备电量 | 当前在线设备与电量，可刷新、右键单台设备 |
| 历史统计 | 24 小时 / 7 天 / 30 天的曲线与当前 / 平均 / 最高 / 最低 |
| 历史管理 | 按设备清理历史、看数据库大小 |
| 设备诊断 | 给未适配设备采证据（见 §9） |
| 设置 | 外观、提醒、采集、插件开关、小组件、日志 |

## 4. 设备电量页

列表里每一行是一台设备。一行里的元素含义：

| 元素 | 含义 |
|---|---|
| 左侧图标 | **设备类型**（键盘 / 鼠标 / 耳机 / 手柄…）。图标形状表示"这是什么" |
| 图标颜色、右侧大号百分比、进度条 | **电量状态**：蓝=充电中，红≤20%，琥珀≤50%，绿>50%，灰=离线或无读数 |
| 设备名后的胶囊徽标 | **连接方式**：蓝牙 / 2.4G / 有线 / 本机。颜色只是辅助，文字才是准的 |
| 徽标后的第二个小标签 | **接收器体系**（Bolt / Unifying / LIGHTSPEED 等）。没登记就不显示，不占位 |
| `⚡` | 正在充电 |
| 设备名下方的小字 | 型号、链路等补充信息 |

- 显示 `----` 表示**还没有读到读数**，不等于 0%。
- 右上角「刷新」重新扫描设备；插上接收器或连上蓝牙设备后需要点一次。
- **单击整行进入详情页**：Hero 显示设备类型或产品图、电量环与状态行，下面分性能 / 连接 / 身份三张卡；DPI / 档位 / 回报率在这里看。产品图来自本机 `device-images` 图片包，没有图时自动回退几何图标（格式见 [../project/device-images.md](../project/device-images.md)）。
- **详情页 Hero 悬停**：图片右下角出现铅笔按钮，点开可以换产品图配色；官方 HUB 不会从设备读取颜色，选错了随时改。
- **右键单台设备 →「自定义名称和图标」**：只改显示名和类型图标；产品图在详情页 Hero 里调。
- **右键单台设备 →「忽略此设备」**——被忽略的设备不再出现在列表、托盘、小组件和贴片里，历史记录保留。
- 多台设备同时在线时，托盘图标显示的是**最低电量那台**。

## 5. 历史统计页

- 三个时间范围：24 小时 / 7 天 / 30 天，切换后曲线与四个指标一起变。
- 四个指标：当前电量、平均电量、区间最高、区间最低。
- 曲线按设备分系列，颜色循环取色（首系列固定是充电蓝）。

## 6. 历史管理页

- 列出所有有历史记录的设备，**包括已离线的**。
- 顶部四个数字：设备数、采样总条数、最早记录、数据库大小。
- 勾选设备后可批量删除。**删除不可恢复**，确认前想清楚。

## 7. 设置页

设置**需要点「保存设置」才生效**（部分项如日志保留天数要重启应用）。顶部有搜索框，可按设置名或品牌名过滤。

### 外观

- **窗口背景**：自动 / 云母 Mica / 磨砂 Acrylic / 纯色。Win10 不支持 Mica 时会自动降级。

### 提醒

- **低电量提醒阈值**：低于该电量弹一次托盘气泡，默认 20%。**填 0 表示关闭提醒**。
- **剩余时间估算**：按近期放电速度估算，显示在设备列表和任务栏悬停提示里。

### 数据采集

- **采样间隔**：多久读一次电量。
- **电量无变化时也按此间隔写一条历史（分钟）**：控制历史库的写入密度。
- **历史保留天数**：超过天数的记录自动清理。
- **监控本机电量**：把笔记本电池也显示在设备列表、小组件和历史统计里。台式机无电池时不显示。

### 2.4G 设备插件（按品牌开关）

一行一个品牌，主标题中文、副标题英文。**默认关闭的是需要向设备发查询帧的品牌**：华硕、MCHOSE、Logitech、雷蛇、索尼 INZONE。纯被动监听的品牌默认开启。

> 打开一个品牌开关，等于授权该品牌的插件向设备发送**只读查询帧**。写入规则见 [../hardware/safety.md](../hardware/safety.md)。

### 桌面小组件

- **显示方式**：固定在桌面 / 普通窗口 / 浮在其它窗口上方。
- **显示内容**：全部在线设备 / 仅最低电量一台。
- **最多显示设备数**：一屏只显示这么多条，其余用滚轮查看；超出部分折叠成 `+N`（选「仅最低电量一台」时此项不生效）。

### 任务栏

- **任务栏电量贴片**：开关。
- **显示屏幕**：贴片钉在哪块显示器的任务栏上；那块屏不在时临时贴主屏。
- **锁定贴片位置**：锁定后按住贴片不会移动。
- **重置贴片位置**：恢复为默认位置（紧贴系统托盘左侧）。

### 日志

- **日志级别**、**日志保留天数**（按日生成，超期自动清理，改后需重启生效）。
- **日志文件**：显示路径，可打开目录、清空日志。

### 其它

- **开机自动启动**：写当前用户的开机启动项（`HKCU\Run`）。
- **启动时最小化到托盘**：开机后直接驻留托盘，不弹主窗口。

## 8. 桌面小组件与任务栏贴片

两者都是**独立窗口**，不进 Alt-Tab、不占任务栏按钮。

- **小组件**：可拖动；右键有菜单。Win10 与 Win11 的圆角、投影表现不同，属已知差异。
- **贴片**：钉在任务栏上，悬停可看设备名与指标（多台时最多三行）。
- 贴片的位置、选屏、锁定都在设置页的「任务栏」组里，贴片自身右键也能切换锁定。

## 9. 设备诊断：给未适配的设备采证据

手里有台读不到电量的设备，不用会抓包也能帮它被支持。主窗口第 4 页「设备诊断」：

1. **选任务**：「未知设备调查（找新协议）」列出系统里全部 HID 设备，未适配的排前面；「已支持设备诊断（排查读数）」只列插件正在认领的设备。
2. **选接口**：每个接口标出有没有输入通道，已适配的设备直接推荐插件实际认领的那个；选中即自动预检，右栏只列需要注意的项。
3. **按步骤采集**：页面给的是操作清单——操作设备 → 连接充电器 → 断开充电器 → 关闭设备 → 重新开启设备，每步实时显示「本步已采到 N 条报文」。
4. **导出**：停止后生成 `report.html` 与 `vigilwatt-capture.zip`，可打开、另存或贴到 issue。

**采集句柄只申请只读权限，不向设备写任何报文**。诊断包可能含设备序列号，发出去前建议自己看一眼包里的 `README.txt`。

页面上还有一个「允许向设备发送（手动发帧，实验性）」的开关，**默认关闭，普通用户不要打开**——那是给协议调查用的写入通道。

三个常见坑：选错接口是最常见的「采不到」（同一个接收器，513 字节的大缓冲通道可能一条都不来，换 19 字节那条就正常）；0 条记录不等于没有协议（有的设备要先开会话才推送）；整场一个字节都没变，多半是配置通道而不是状态通道。

## 10. 数据在哪

数据目录与安装目录分开，按优先级取第一个可用的：

1. 环境变量 `VIGILWATT_DATA_DIR`（显式指定，调试/隔离时用）；
2. **便携版**：解压根目录的 `data\`（根目录带 `.portable` 标记）；
3. **安装版**：`%LOCALAPPDATA%\VigilWatt`。

里面是 `history.db`、`settings.json` 和 `logs\`。**要彻底清干净，需要手动删这个目录**——它不在安装目录里，卸载程序管不到。

## 11. 遇到问题

先查 [../README.md](../README.md) 的「症状速查」表，再按对应专题文档排查。设备读不到电量的排查入口是 [../hardware/debugging.md](../hardware/debugging.md)。
